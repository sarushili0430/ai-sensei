承認 2026-08-03

## 0002 agent は TypeScript(Node 22)

承認 2026-08-03

- ガードレール・プロンプト・契約を api と agent で**1実装**にできる
- Python にすると二重実装になり、ソロ開発では片方が必ず腐る
- `.ts` を型ストリップで直接実行する。ビルド手順を持たない

- **Dockerfile はリポジトリのルートに置く**。`lk` は作業ディレクトリを
  そのままビルドコンテキストにし、`workspace:*` はルートでないと解けない

**却下** — 焼いたイメージを渡す(`--image` は Enterprise 限定)/
`backend/agent` を別リポジトリに切り出す(1実装にした理由が消える)。

## 0003 `/complete` の内部認証は共有静的トークンのまま

承認 2026-08-04

- MVP提出までは据え置く。作り替えは agent の稼働先が決まってから一度で行う
- この値はクライアントに渡っていない。server↔server 限定
- `INTERNAL_API_TOKEN` は**環境ごとに別の値**にする。ログに出さない
- 目標の形はセッションスコープの短命トークン(`sub`/`aud`/`exp` 付き)
- 署名鍵は Workers だけが持ち、agent は長期鍵を持たない
- 部品は `lib/livekit.ts` の HS256 実装で足りる。新しい依存は要らない

**却下** — LiveKitトークンの `metadata` に載せる。その JWT はアプリに
そのまま返しており、base64 decode で読める。アプリがカルテを偽造できる。

**見直す条件** — 提出後のW4 / agent の稼働先が決まったとき /
自分以外が agent の実行環境に触るようになったとき。

**残るリスク** — agent の実行環境が漏れると全セッションのカルテを偽造できる。

## 0003 ~~声は Deepgram に一本化(STT + TTS)~~

承認 2026-08-06 / **TTSは [0008](#adr-0008) で Gemini へ移した(2026-08-19)**

英語は別モデル)は取り消す。聞く側の `nova-3` は据え置き。

## 0004 動きは1経路に集約し、オンボーディングで1往復させる

承認 2026-08-06

- 装飾のモーションは必ず `AppMotion` を通す。減らす設定では**出さない**
- 出さないときは**終わった状態**を描く。0で止めると壊れて見える
- 例外は操作の時間(`AppDurations.hold`)。長押しの長さは説明の比喩なので縮めない
- 読み上げ中(`prefersTapOverHold`)は長押しをタップに切り替える
- テストは常に `disableAnimations` で回す。通し忘れたループはテストが返らず露見する
- 蛍光マーカーは**行ごと**に、上の行から順に引く
- オンボーディングは4枚。3枚目でリハーサル(写真も声も使わない・権限も要らない)
- 説明してもパスしても先へ進める。3枚目から「とばす」を出し、行き止まりを作らない

**却下** — Rive への載せ替え(v1.1)/ 効果音 / オンボーディングでマイクを試させる /
リハーサルを必須にする。

**追記 2026-08-11** — ピボットで約束1が「教える。そのあと教え返させる」に改正され、
3枚目は「先輩の板書で教わったあと教え返す」に置き換わった。上の1・2・4行目の判断は有効。

**追記 2026-08-24** — [0009](#adr-0009) で教え返しとカルテを畳んだので、
**~~オンボーディングは4枚~~ → 5枚(日本語は6枚)**に組み直した。
動きの1経路(上の1〜5行目)と「行き止まりを作らない」は有効なまま、中身だけが替わっている。

- 並びは **約束 → 学年(日本語のみ)→ やること → 授業のリハーサル → 復習のリハーサル → これから**
- **リハーサルは2つになった。**前半(板書で教わって「わかった」を押す)だけでは、
  手元の無料AIとの差である**後半(3日後に聞きにいく)**が文字の説明のままになる。
  通知 → 解答 → 採点までを、繋がずに1往復させる
- **学年を1問だけ聞く。**既定は高校生なので、聞かないと中学生が黙って高校の単元を
  候補にされる([0007](#adr-0007))。海外課程は段階を持たないので**英語では出さない**
- 進み具合は点ではなく**棒**。枚数が増えたぶん「あとどれだけか」が要る
- 「とばす」を出し始めるのは**やってみる枚から**(前半は飛ばさせない)。
  学年だけは「とばす」を出さずに選択で止める — 選択肢2つに正解/不正解が無いため

**却下(このとき)** — ~~オンボーディングで通知の許可を求める(権限は文脈の中で聞く決まりを崩す)~~
(**下の追記で取り消した**)/
復習のリハーサルでキーボードを出して打たせる(まだ何も起きていないうちに手間だけが先に来る)/
学年を英語でも聞く(答えが何も変えない質問になる)。

**追記 2026-08-25** — 通しで触った結果、**言葉を削って、通知だけ先に聞く**。
枚数と並びは変えていない。

- **通知の許可は最後の枚で聞く**(`_OnboardingScreenState._finish`。「はじめる」も
  「とばす」も同じ出口を通る)。上の却下を取り消す。理由は、**このアプリの再訪が
  全部通知が起点**だから — 3日後・7日後に届かなければ ADR 0009 の後半はそもそも
  始まらない。それまで聞く場所は設定のトグル1つだけで、**自分で辿り着いた人しか
  許可していなかった**。カメラとマイクは今までどおり使う直前に聞く
- **予告の一文を全部消した**(「カメラ・マイク・通知の許可は、使う直前にお願いします」/
  「ここではまだ、写真も声も使いません」/「待たなくて大丈夫。次に会うのは通知の中。」/
  「減点はしません。」)。使う直前に聞くなら予告は要らないし、**まだ何も起きていない
  画面で「使いません」と言われても、何のことか分からない**。約束は言葉ではなく
  1周やってみることで伝える、という上の判断がそのまま延びた形
- **「もう一度ためす」を消した。**リハーサルは1往復すれば済む。やり直す口を残すと、
  一手押しただけの枚に選択肢が2つ並ぶ
- **解答はタップ待ちにせず、開いた瞬間から書かれる。**「タップして書く」の薄い文字が
  座っているだけでは、そこが解答欄だと気づかれないまま通知の枚が終わる
  (キーボードを出さない判断は据え置き)
- **枚が自前の一手を持っているあいだは「つぎへ」を出さない。**「開いてみる」「こたえる」の
  真下に押せない「つぎへ」が並ぶと、どちらが今の一手か分からない

## 0005 英語対応は訳さない。課程ごとに別で持つ

承認 2026-08-07

- カリキュラムはロケールごとに別ファイル。`ja` は数学I〜C、`en` は Algebra 1 〜 Statistics
- 対応表は作らない。ずれた場所は**どちらの課程でもない単元**になる

- 端末の言語は「日本語を望んだ人にだけ日本語」。それ以外は英語へ倒す

**却下** — 日本の課程を英訳する / ロケールをDBのセッション行に持つ /
1本のカリキュラムに両課程を入れる。

## 0007 課程(track)を指導言語から切り離す

承認 2026-08-12

- [0005](#adr-0005) の「ロケール」は3つを兼ねていた: どの課程か / 先輩が話す言語 /
  ガードレールの語彙
- 「日本の中学生が英語を学ぶ」= **課程は英語・指導言語は日本語**で、1つの値では表せない
- `CurriculumLocale`(`ja`/`en`)は**指導言語のまま据え置く**。課程は `TrackId` に切り出す
- `Record<CurriculumLocale, …>` も `plan_sessions.locale` の CHECK も無傷。
  保存済み topic_id も変えないので**マイグレーションはゼロ**
- 接頭辞から引くものが2段になった: 接頭辞 → 課程 →(言語, 教科, 学校段階)。
  [0005](#adr-0005) の「IDひとつから言語が決まる」は強化されて残る
- 1 track = 1 JSONファイル。`Record<TrackId, Curriculum>` なので登録漏れは型で落ちる
- **`topicsFor(locale)` は消した。** 残すと課程が増えた日に無言でプロンプトが倍になる
- 学年は表示専用の `grade_hint` に隔離。`suggestTopics` / `resolveDetectedTopics` に
  **学年を渡す引数を作らない**のが「学年で絞らない」の実体
- 指導要領は中学英語の文法事項を学年配当していない(付録7は「中学校」一括)。
  中学英語の courseCode を学年別にしないのも同じ理由
- 前提の参照は「同じ課程」から「**同じ言語・同じ教科**」に緩めた。
  高2を中3へ戻すのは先輩の中核機能なので、段はまたいでよい
- `school_stage` はリクエストごとに受け取り、DBには持たない。既定は `high_school`
- 板書に使える要素は教科で閉じる(数学=数式系 / 英語=`sentence`・`compare`)。
  英語の課程では LaTeX の検査に到達しない
- 高校英語の文法は付録9の8項目。中学に無いのは関係副詞だけなので、
  残り7つは複製せず `prerequisites` で中学英語を指す

**代償** — 接頭辞は3か所で二重管理のまま(`curriculum/schema.ts` /
`contract/karte.ts` の正規表現 / モバイルの `planSubject`)。contract が依存を
持たない層である以上ほどけないので、**全コースコードで既定に落ちないテスト**で縛る。
`school_stage` は再インストールで選び直しになる。

**却下** — `CurriculumLocale` に `"ja-english"` を足す(`Record` の意味が
「言語ごと」から「課程ごと」に化け、CHECK 制約も書き換えになる)/
topic_id を `{教科}-{課程}-{単元}` に作り直す(保存済みIDを全部書き換えることになる)/
学年を courseCode に入れる(指導要領が定めていない配当を仕様に格上げしてしまう)。

## 0008 喋る側だけ Gemini TTS へ移す(聞く側は Deepgram のまま)

承認 2026-08-19

- 限界は**日本語ボイスが英語を喋れない**こと。英語も教える([0007](#adr-0007))のに、
  日本語の授業に混ざった英単語だけ読めない声で先輩をやらせていた
- 数式記号も同じ。`toSpeakableJa` の手当ては残すが、想定外の記号で崩れる余地が減る
- **声は日英で1つ。**Geminiのボイスは言語がモデル名にも声名にも埋まっていないので、
  ロケールで先輩が別人にならない([0003](#adr-0003-voice) では別モデルだった)
- `Leda`(youthful)に固定。落ち着いた大人の声だと**先生**になり、教え返しを頼む相手として遠い
- 既定は `gemini-2.5-flash-preview-tts`。3.1(`gemini-3.1-flash-tts-preview`)は
  `GEMINI_TTS_MODEL` を入れた人だけが踏む
- **TTSモデルは3つとも preview で、GAは無い**(2026-08 時点)。「モデルが消えた日に
  先輩が無言になる」リスクはどれを選んでも避けられないので、**コードを変えずに
  環境変数だけで逃げられる**形にしてある
- **プラグインの `GeminiTTSModels` 型を信用しない。**`gemini-2.5-flash-tts` /
  `gemini-2.5-pro-tts` という存在しない名前が入っている。`model` は
  `GeminiTTSModels | string` でAPIへ素通しなので、型は実在を保証しない
  (存在しない名前でも起動は通り、最初に喋る瞬間に落ちる)。
  実在するIDは `senpai-voice.ts` の `geminiTtsModels` が正
- 聞く側(STT)は Deepgram `nova-3` のまま。**JSのGoogleプラグインにSTTのクラスが無い**
- Gemini TTS は**ストリーミングを持たない**。`tts.StreamAdapter` でこちらから包み、
  日本語の文分割器を渡す。包み忘れるとSDKが既定の分割器を当てて「。」で切れなくなる
- **1文 = 1リクエスト**になったので、文分割器の切り方がそのまま最初の音までの待ちになる
- 冒頭の同梱音声も同じ声で焼く。モデル名・声名・読み方の指示は `senpai-voice.ts` に1本化。
  2箇所に書くと片方が古くなり、**冒頭の一言だけ別人が喋る**

**代償** — 鍵と請求先が2つに戻る([0003](#adr-0003-voice) の「一本化」はここで終わる)。
previewモデルの寿命はGoogleが決める。合成が生成モデルなので、読み方の指示に
「省くな・足すな・訳すな・答えるな」を毎回添える必要がある。

**却下** — Gemini Live API(realtime)への全面移行(STT・LLM・TTSを1本にすると
板書の配送と授業ループを作り直すことになる。声の問題を直すには高すぎる)/
会話LLMまでGeminiへ替える(板書とカルテのプロンプトはClaude前提で書いてある)/
`toSpeakableJa` を外す(「にぶんのいち」のような日本語の数学の読み順は、
モデルの気分に任せる場所ではない)。

**見直す条件** — TTSにGAのモデルが出たとき / STTのGoogleプラグインがJSに来たとき /
Live API が板書の配送を壊さずに使えると分かったとき。

## 0009 教え返しとカルテを畳み、「わかった」→ 採点つき復習問題 → 通知の一本道にする

承認 2026-08-24

- 授業ループの**回数上限を撤廃する**(`defaultMaxLessonPasses = 6`)。6周は
  ユーザーの理解と無関係な数字で、そこで切れた生徒は途中で放り出されていた
- 降りる口は**生徒側に2つ**。画面下の「わかった」(到達の宣言)と、
  ヘッダ左上の ×(離脱)。下に置く操作を1つに保つ決まり([0006](#adr-0006))は崩さない
- **確認を挟むのは × だけ。**「わかった」は素通し(押し間違えても次のセッションで
  撮り直せる)。× は復習問題ごと失う道なので一度止める
- **教え返しを廃止する。**「じゃあ今の、説明してみて」の往復ごと畳む
- **カルテを廃止する。**復習問題の履歴へ一本化。穴を見ていた画面は消さず**単位を替える**
- 復習問題は**板書から作る**。まず1問。本人の発話ではなく、先輩が教えた内容が材料
- **AI が採点する。**`verdict` は `correct` / `incorrect` / `unclear`。
  解答形式はテキスト入力(通知から開いた場所で声を出せるとは限らない)
- **合否に関わらず履歴に積む。**変わるのは通知の段だけ —
  不正解 = 1・3・7日 / 正解 = 3・7日 / 判定できず = 予約しない
- **作った直後は 3・7日**(= 正解と同じ扱い)。「わかった」は到達の宣言なので、
  押した翌日に「まちがえた問題」と同じ間隔で届くと、**押したこと自体が罰になる**
- **作成時に決めた段は取り消さない。**3日目に正解したから7日目を消す、はやらない
  (「1回言えたら終わり」に戻り、間隔反復の効き目が消える)
- **生成のトリガーは「わかった」だけ。**時間切れ・離脱では作らない
  (教わりきっていない内容を問わないため)
- **生成の完了を待たせない。**押した瞬間に部屋を閉じ、生成は `/complete` の裏。
  最初の接触は通知。待ち合わせを作ると #175 で直した穴を作り直すことになる
- テーブルは新しく3枚(`practice_problems` / `practice_attempts` / `practice_schedules`)。
  **`holes` には触らない**(既存データは読めるまま残す)
- **デプロイは API を先、agent をあと。**新しい agent × 古い API だけが 400 で落ちる
  (`completeSessionRequestSchema` は `.strict()`)。逆向きは復習問題が作られないだけで
  完了する([deploy.md](deploy.md))
- **UI は [`docs/core_loop_screens.html`](core_loop_screens.html) が正。**新しく決める余地は
  残していない — 色・字送り・当たり判定まで `tokens.dart` / `board_style.dart` /
  `app_theme.dart` の実値から起こしてある。実装で迷ったらあの図を見る

### これが取り消す既存の約束

**黙って変えない。**同じ場所に新しい理由を置かないと、半年後に誰か(自分を含む)が
「バグだ」と言って戻す。

- `prompts/karte_generation.ja.md` §出題 —「出題元は `<transcript>` の `ユーザー:` の
  行だけです。`先輩:` の行から作らないでください」。**反転した。**板書が材料になる
- 同 —「**答えを書かないでください。採点はしません。**本人が『言えた / まだ言えない』を
  選ぶだけです」。**反転した。**正解を持ち、AIが採点する
- `packages/contract/src/karte.ts` の `quiz` / `reviewOutcomes` のコメントも同じ内容を
  持っていた。型ごと `@deprecated` にしてある
- ピボット計画 §2「小テストの出題元はユーザーが説明した内容で、AIが教えた内容から
  作らない」

反転した理由は1つ。**教え返しが無くなると、本人が説明した内容そのものが手に入らない。**
AIの誤読を間隔反復で3回強化する危険は残るが、それは採点(`unclear` を持つ)と
`board_id` による材料の追跡で受ける。

**代償** — 親レポートの `quotes` が素材を失う(`kartes.said_well` から引いていた)。
代替は復習問題への解答で、テキスト入力なので本人の言葉がそのまま残り、
`correct` のものだけ選べる。/ 会話LLM(Haiku 4.5)の出番がほぼ消え、セッションの原価は
Sonnet 5 の板書だけになる。/ **「わかったつもり」を検出する手段が無くなる** —
それを担っていたのが教え返しだった。採点が代わりを務められるかは出してみないと分からない。/
④'(途中で降りた)に落ちた生徒には、次に開く理由が残らない。

**却下** — 教え返しを残したまま復習問題を足す(セッションが長くなり、20分の枠に
授業が入りきらない)/ 採点しないまま板書から出題する(答えを持たない問いを
先輩が教えた内容から作ると、誤読を確かめる手段が無いまま3回通知することになる)/
`holes` に `answer` 列を足して相乗りさせる(`filled` が「言えた」と「正解した」の
2つの意味を持ち、`computeProgress` の数字がどちらか読めなくなる)/
`unclear` を `incorrect` へ倒す(モデルの迷いが生徒の記録として残る)。

**見直す条件** — 「わかった」が押されないまま時間切れになる回が多数を占めたとき
(押しにくい文言か、押す場所が悪い)/ `unclear` の比率が高止まりしたとき
(採点プロンプトか、テキスト入力という形そのものが合っていない)。

**追記 2026-08-25(授業画面: 番と間)** — 実機で通したら、**誰の番なのかと、
喋る速さ**の2つが出た。どちらも板書の下の1行と、読み上げの間の話。

- **「いまは誰の番か」を3つに割る**(`SessionTurn`)。それまで板書の下は状態に
  関係なく青い点+「先輩が説明中」しか出しておらず、**黙っているのが「答えを
  待っている」なのか「次を考えている」なのか画面から読めなかった**。印で分ける:
  先輩が喋っている = 青い点 / 先輩が考えている = **円のローダー** /
  こちらの番 = **3本の波**(`SpeakingWave`。既存の「聞いています」の絵)
- **判定は板書が持つ。**`awaits_student` が立っている手順で止まっていれば生徒の番、
  立っていなければ先輩が考えている。フェーズ(`explainBack`)はどちらでも同じ値なので
  割れない。**欄はLLMが書き忘れる**ので、agent は言い回しの推測で止めた手順にも
  立ててから送る(`board.ts` の `handsOver`)—— 欄が空だと画面は「考えています」の
  まま回り続け、**どちらの番かが消える**
- **手順と手順のあいだに間を置く**(`speech-pace.ts`。既定 700ms)。再生の終わりで
  手を離すと次の行が同じ息で始まり、板書を目で追っている生徒が置いていかれる。
  1手順の中の文と文はTTSへの指示で空ける(`sentencePacingInstruction`)
- **「問題を追加」を画面から外した。**授業中に別の問題を足す口で、板書の上に常駐して

**却下(このとき)** — 番を `AgentState` だけで決める(`thinking` は授業中に来ない。
返事は `StopResponse` で止めているので、SDKの返答パイプラインが回らない)/
