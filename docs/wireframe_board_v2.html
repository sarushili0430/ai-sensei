契約にある5要素(latex / text / plot / triangle / circle)は、すべてこの面の上で成立する必要がある。

1. 面
濃い緑〜濃紺。真っ黒にしない(本文の ink を真っ黒にしていないのと同じ理由)。ここが変わるだけで、残り5つは効きが倍になる。
2. 画面いっぱい
左右の端まで伸ばす。板は面であってカードではない。同時にこれが、実効幅を減らさずに面を作る唯一の形。
3. 縁と粉受け
上下の横木。粉受けは「黒板である」ことの最短の記号で、しかも板がどこで終わるかを同時に示せる。
4. チョークの字
白を95%の不透明度で。わずかな滲みを乗せる。書く動きは既にある — BoardReveal の左→右のワイプ(420ms)は、そのままチョークの動きとして読める。
5. 線でやる強調
下線・二重下線・囲み・矢印。黒板の強調はもともと色ではなく線。青やピンクは板の上では浮く。
6. 見出し
板の左上に小さく「先輩の板書」。いまはヘッダに board.title があるだけなので、板の中に入れると帰属が閉じる。

通知の許可細い 許可を聞く場所がカルテ画面のトグル1箇所だけ。文脈内で聞く方針は正しいが、カルテを一度も開かなかった人には再訪の入口がホームカードだけになる。授業を1回やって離脱した人がここに落ちる
「まだ」の行き先決めが要る 声で聞き直すのは Premium + 日次枠。無料だと「まだ」を押した先がペイウォールか、閉じるかしかない。穴を認めた直後に課金を出すのが、この製品の約束と噛み合うかどうか
自習室から欠けている 自習室が行ける先は撮影だけ。こもっている最中こそ「きのうの穴を1つ」が効くはずだが、導線が無い
計画との接続欠けている A節と同じ穴。計画に「きのうの穴を1つ」が並んでも、そこから復習画面へ行けない

3つに共通しているのは「作る筋は通っているが、読む側の配線が無い」という形。 計画・レポート・復習はどれも単体では完成していて、互いを知らない。 次に足すとしたら新しい画面ではなく、ホームと自習室から他へ伸びる線だと思う。

D. 図形の表現力 — 描かれない理由と、描けないものの一覧

「図を描いてくれない」と「平面図形・空間図形がひどい」は別々の問題だった。 前者はプロンプトの問題で今日直せる。後者は契約の問題で、 いまの5要素では高校数学の図の大半が原理的に描けない。 事前に分かる形にしたのが以下。

D-1. なぜ描かれないか — 3つとも、絵を出させない側の理由だった

契約もガードレールも図形を弾いていない。落としているのはプロンプトと、記憶の畳み方。

原因効き中身
見本に図形が1つも無いいちばん重い senpai_board.ja.md の見本に出てくる要素を数えると latex が5・text が1・図形は0(英語版も同じ)。 LLMは表よりも見本を真似る。1度も見たことのない形は出てこない。
「いつ図にするか」が書いていない重い 388行のプロンプトのうち、図形に触れているのは要素表の3行だけ。 「同じ説明を繰り返さない — 数値を入れてみる、図にする、逆から考える」と一箇所あるが、 どの単元で何を描くかの指示は無い
描いた図が、記憶から消える効く describeBoard(senpai.ts:208)が過去の板書を1行に畳むとき、 三角形は座標が全部消えて「三角形 ABC」、円は中心が消えて「円 r = 3」になる。 先輩は自分がどこに何を描いたか読み返せないので、図の続きを描けない

1と2はプロンプトだけで直る(見本を3つ足して、単元ごとの目安を1節書く)。 3は describeBoard に座標を残すだけ。どれも契約に触らない。 ただしこれで描けるようになるのは、次のD-2で「○」が付いているものだけ。

D-2. 描けるもの3つと、描けないもの

いまの図形プリミティブは plot / triangle / circle の3つだけ (latex と text は文字)。この3つが単独で置けるだけで、組み合わせはできない。

以下は全部、いまは描けない。どれも高校数学では図が主役の単元で、 式や言葉で代用すると、まさに「わかった気」だけが残るところ。

D-3. 限界の一覧 — 事前に知っておく10項目

契約(board.ts)と描画(*_painter.dart)を読んで確定させたもの。 1番がいちばん効くで、これがある限り2〜10を個別に足しても平面図形は解けない。

  • 1重ねられない。1要素 = 1つの図で、それぞれ独立した箱(高さ180)に別々の縮尺で描かれる。円と三角形を同じ絵にできない。外接円も内接円も原理的に無理
  • 2線分が引けない。任意の2点を結べるのは三角形の3辺だけ。中線・垂線・接線・弦・対角線・補助線が全部引けない
  • 3点が打てない。単独の点は plot の marks だけ = 関数の上にしか置けない
  • 4多角形が無い。四角形・台形・正n角形。頂点はちょうど3つと z.tuple で固定されている
  • 5塗れない。面積も領域も確率も、範囲を示す手段が無い
  • 6矢印が無い。ベクトルが描けない(数C の3単元が丸ごと該当)
  • 7z が無い。boardPointSchema は {x, y}。空間図形はゼロ
  • 8plot は y = f(x) が1本だけ。2本目も、縦線 x = a も、媒介変数も、極座標も無い。楕円・双曲線は関数で書けないので描けない
  • 9角の印は三角形の頂点だけ。円周角も、2直線の交角も示せない
  • 10数直線が無い。不等式の解を数直線で見せられない

packages/curriculum の52単元のうち、図が主役または図があると効くのは30単元。 そのうちいまのまま描けるのは6、部分的が5、残り19は手が出ない。

「平面図形・空間図形がひどい」は、実装の粗さではなく契約の範囲そのもの。 数A「図形の性質」3単元と数C「ベクトル」3単元は、1つも描けない。 いま plot で足りているのは関数のグラフだけで、 それはたまたま「1本の曲線」が1プリミティブに収まっているから。

D-5. どう埋めるか

3段に分けて考えている。1段目は今日やれて、2段目が本命。3段目は「やらない」と決めるほうの判断。

すぐ1. プロンプトを直す

見本に plot / triangle / circle を1つずつ足し、 「単元ごとに、いつ図にするか」を1節書く。describeBoard に座標を残す。 契約に触らない。

効果はD-4の「描ける6単元 + 半分5単元」まで。 いま描けるはずのものが描かれていない、という取りこぼしだけが直る。

本命2. 図を「1枚の絵」にする

segment や polygon を要素として並べても意味が無い(限界1)。 要るのは1つの図の中に複数の部品を置ける器 — figure { items: [point, segment, polygon, circle, arc, arrow, label] }。 縮尺は器が1つ持つ。

これで平面図形・ベクトル・領域・接線がまとめて入る。 「自由描画をさせない」という原則は壊れない — 部品は列挙型のままで、 LLMが吐くのは相変わらずパラメータだけ。増えるのは部品を組み合わせる自由だけ。

判断3. 空間図形は、やらないと決める

3Dの投影をLLMにパラメータで吐かせるのは、平面と桁が違う難しさ (見え隠れ・投影角・補助線)。やるなら別の作りになる。

正直な選択肢は2つ。(a) 空間の単元を許可リストから外して「まだ教えられない」と言う。 (b) 図なしで式と言葉だけで教える、と決める。 いまは(b)を黙ってやっている状態で、それがいちばん悪い — 生徒は先輩が図を出せないことを知らない。

順番は 1 → 2。1をやらずに2をやると、器を足しても見本が無いので相変わらず描かれない (いまと同じことが、もっと大きな契約の上で起きる)。 逆に1だけで止めると、D-4の19単元は永久に描けないままになる。

D-6.「2」は具体的にどう書くのか — 座標を出させない、という一点

素直に {"kind":"figure","items":[{"point":[3,4]}, …]} と生の座標を並べる形にすると、 схема は表現できても中身が壊れる。 円周角なら3点が円の上に乗っていないといけないし、接線なら傾きが f′(a) と一致していないといけない。 LLMにその計算をさせると、それらしく見えて実は乗っていない図ができる — このプロダクトがいちばん嫌っている「わかった気」を、こちらから作ることになる。

なので座標ではなく「作図の手順」を書かせる。点の位置は受け取った側が計算する。 いまの原則「LLMにはパラメータだけ吐かせる」が、「LLMには関係だけ吐かせる」に一段強くなる形で、 自由度はむしろ減る。 

figure {
  items: [                       // 順に解いて、順に描く
    { pt: "O", at: [0, 0] }              // 生の座標を書いてよいのは「置くだけの点」だけ
    { circle: "C", center: "O", r: 5 }
    { pt: "A", on: "C", deg: 210 }       // ← cos/sin はこちらが計算する。必ず円の上に乗る
    { pt: "B", on: "C", deg: 330 }
    { pt: "P", on: "C", deg:  80 }
    { seg: ["P","A"] }  { seg: ["P","B"] }  { seg: ["A","B"] }
    { arc: ["A","P","B"], label: "θ" }   // ∠APB。角度も測ってこちらが描く
  ]
}

// 派生点(これがあるから「五心」「接線」「垂線の足」が正しく描ける)
{ pt: "M", mid: ["B","C"] }              // 中点
{ pt: "G", centroid: ["A","B","C"] }     // 重心
{ pt: "H", foot: ["A", "B","C"] }        // A から直線BC へ下ろした垂線の足
{ pt: "X", meet: [["A","M"], ["B","N"]] } // 2直線の交点
{ pt: "T", on: "curve1", x: 2 }          // 曲線上の点
{ tangent: "curve1", at: "T" }           // 接線。f′ は数値微分でこちらが出す
{ fill: { under: "curve1", from: 0, to: 3 } }   // 面積の塗り
{ arrow: ["O","A"], label: "a" }         // ベクトル

接線の f′ は、もう計算できる。plot_expression.dart が式を評価できるので、 数値微分は数行で足りる。新しい数式処理系は要らない。

この場で解いて描いたもの(下の図は、上のJSONから計算した結果)

いずれも点の座標はほとんど書いていない。書いてあるのは「円の上の何度」「中点」「重心」 「2円の交点」「垂線」だけで、位置はこのページのスクリプトが計算している。 後半3枚は実際の入試問題の図で、実装でも同じことを Dart 側でやる。

3枚目と5枚目が要点。3本の中線が1点で交わるのは目分量ではなく centroid が 計算した点だから。5枚目の AD ∥ BC はどこにも指定していないのに、 出来上がった図では向きの差が 0.000° — 証明すべき結論が、作図の結果として勝手に現れている。 これは正しく作図できていることの、いちばん強い証拠でもある (生の座標をLLMに書かせていたら、ここは必ずズレる)。

D-7. 段階と、実装で触る場所

全部いっぺんには要らない。単元の回収数の多い順に4段。1段目だけでも数A図形の性質3単元が入る。

D-8. 代案 — 速い画像生成AIに描かせる

実行時に描かせるなら反対。事前に描かせるなら賛成。 同じ「AIに絵を描かせる」でも、いつ描くかで性質が正反対になる。

見るところ実行時に生成(授業中に1枚ずつ)作図(D-6)
正しさ 保証できない。点が円から浮く・接線が曲線を突き抜ける・ラベルが化ける 構造で保証される。「円の上の75°」としか書けないので、乗らない事故が起こりようがない
検証 これが決定的。出てくるのはピクセルなので、「Pは本当に円の上か」を機械で確かめる方法が無い。間違いに気づけるのは、すでに分かっている人だけ データなので検査できる。解けなければ paintBoardElementError に落ちて、黙って嘘を出さない
原価とテンポ 板書は1手順ずつ流れる作り(BoardReveal 420ms)。1枚ごとに生成待ちが挟まると、書きながら教えるリズムが切れる。§3-1 がTTS文字数をスキーマで縛ってまで守っている原価に、画像の従量課金が乗る JSONが1行増えるだけ。追加の原価はゼロ
読み上げ ラスタ画像に意味は無い。alt文をもう一度モデルに書かせることになり、検証できない層がもう1つ増える 作図の手順が、そのまま読み上げ文になる(「円Oの上に点A、B、P。∠APB」)
原則 「自由描画をさせない」を正面から破る。あれは見た目の話ではなく、幻覚がワイヤーに流れない構造を作るための約束 部品は列挙型のまま。自由度はむしろ減る
空間図形 ここだけ強い 作図では届かない唯一の領域に手が届く。ただし正しさを確かめられない問題は、空間でこそ最悪になる(投影が狂った立体は、平面より気づきにくい) 届かない。D-5の3で「やらない」と言った範囲

ただし、描く時点をずらすと評価が変わる。 実行時ではなくあらかじめ描かせ、人が1度見て通すなら、弱点が全部消える。

賛成事前生成 + 人の確認 = 図のカタログ

単元ごとの定番の図を先に作っておく(52単元 × 数枚)。人が1度見て、通ったものだけ入れる。 先輩は授業中には図のIDを選ぶだけ。

正しさは人が保証・待ち時間ゼロ・実行時の原価ゼロ・読み上げ文も人が書ける・見た目も揃う。 作る手段は何でもいい(画像生成でも、人が描いても)。 「速いAIに描かせる」が効くのは、まさにここ。

弱点は1つだけ、しかし大きい: その生徒の問題に合わない。 円周角の定理そのものの図は出せるが、生徒が撮った「その三角形」は出せない。

気づき空間図形はカタログ向き

空間図形は問題ごとに図が変わるというより、定番の配置の繰り返し (直方体・正四面体・切断・回転体)。 種類が知れているので、カタログで先に用意できる。

つまりD-5の3(空間はやらない)は、カタログを前提にすれば覆せる。 solverで空間を解こうとするより、定番の立体を数十枚用意するほうが現実的。

住み分けの結論。 その生徒の1問に合わせた図 = 作図(solver) — 正確さが要るところ。 定理・概念の定番の図 = カタログ(事前生成) — ここで画像生成を使う。 空間図形 = カタログのみ。 この3つは競合ではなく、担当が違うので、どれかを選ぶ話ではない。 ただし先に効くのはカタログのほう — solverを書かずに今週作れて、D-4の19単元のうち 「定理の説明」で足りるぶんはそれで埋まる。

D-9. 図をどう作るか — 判断の全体

3つの方法は競合ではなく担当が違う。分かれ目は「その生徒の1問に固有かどうか」の一点。

やる順は「プロンプト → カタログ → 作図」。 カタログはsolverを書かずに作れて、しかも空間図形に唯一手が届くので先。作図はその後でいい。 ただしD-1のプロンプト修正だけは、どちらより先 — どちらを作っても、見本が無ければ先輩は図を出さない。

D-10. 組み合わせは無限 — だからカタログの中身は「絵」ではなく「型」にする

問題が複雑になれば配置の組み合わせは無限に出る。その通りで、これがカタログの設計を決める。 絵を並べたカタログは、この時点で負ける — 枚数がいくらあっても、次の問題の配置がそこに無い。 なのでカタログに入れるのは1枚の絵ではなく、スロットの空いた作図の型にする。

負ける絵のカタログ

en-shuhenkaku-01.png のような完成した絵を並べる。

配置が1つ違えば別の絵が要る → 枚数が配置の数だけ要る = 無限。 人のレビューも1枚ずつ必要。「過不足なく」が原理的に決まらない。

勝てる型のカタログ

作図の手順を、数値だけ空けた状態で置く。絵ではなくD-6のスクリプト。

型の数は定理の数だけ = 有限。配置の無限はスロットが吸収する。 人のレビューは型に1回で済む — 構成で正しさが決まるので、どの数値を入れても正しい。 

figures/en-shuhenkaku.json        // 円周角の定理。1つの型が、配置の無限をぜんぶ受ける
{
  topic_ids: ["MA-ZUKEI-EN"],   // 索引は既存の許可リストと同じ topic_id
  slots: { a: 205, b: 335, p: 75 },   // ← ここだけ先輩が決める(既定値つき)

D-11. 型ですら届かない問題 — そこで効くのは語彙のほう

チェバの定理の練習問題(三角形と3本のチェバ線)は定番の配置なので型で書ける。 けれどその次に来る入試問題は、型に無い。 たとえば「AD と BE が F で垂直に交わる。BD:DC = 3:2」という配置は、 どの定理の標準図でもない — その問題のためだけの配置で、 当然そんな型は用意できない。

ここが分岐点だった。この配置は型では書けないが、作図でなら書ける — 上の4枚目がそれで、実際に灘中の問題の図をこのページで組み立てている。 効いているのは型の数ではなく、部品の語彙のほう:

  • 1内分点 — 「BD:DC = 3:2」が { on:["B","C"], ratio:[3,2] } とそのまま書ける
  • 2垂線 — 「BE は AD に垂直」が、条件ではなく作り方として書ける
  • 3交点 — E も F も、座標ではなく「どの2本の交わり」かで決まる

つまり3段になっていて、下ほど強い。カタログは中段のショートカットにすぎず、 solverの代わりにはならない。

段覆える範囲限界
絵
1枚の画像		 その配置ちょうど1つ 配置が1つ違えば別の絵が要る。入試問題には原理的に追いつかない
型
スロット付きの作図		 定理の標準図(約50)。数値が変わっても同じ図でいい場面 「その問題のための配置」には型が無い。チェバの練習問題までは届き、灘中の問題には届かない
作図
部品を自由に組む		 作図の手順に書き下せるものすべて。灘中の図もここ 手順に書けない配置は残る(条件を同時に満たす形を探すタイプ)。ただし入試問題の多くは作図の手順に書ける

残る本当のリスクは、語彙ではなく「順序を思いつけるか」。 灘中の図を描くには、先輩が「E は、B を通り AD に垂直な直線と AC の交点」だと気づく必要がある。 これは書き写しではなく幾何の読み替えで、間違えれば図も間違う。 ここだけは、スキーマでは守れない。

ただし、これは測れる。過去問から図つきの問題を数十問集めて、 「作図の手順を書かせて、解けた図が原図と同じ構造か」を機械で照合できる (点の個数・どの線分上にどの点があるか・直角の位置)。 正しさが検証できるのが作図の利点なので、精度は数字で出せる — 画像生成でこれをやろうとすると、照合する相手がピクセルしか無い。

もうひとつ、実務上の救い。教科書の図はそもそも縮尺どおりではない。 灘中の図も「AB:CF = 3:2」を満たすようには描かれていない — 満たすべきは、点がどの線分の上にあるかという構造と、直角の印だけ。 数値は文章とラベルが持つ。だから作図が満たすべき条件は、見た目より少ない。

D-12. 実際に試した5問 — 境界はここだった

出してもらった問題を順に作図で書いてみた結果、境界は「難しさ」ではなかった。 灘中も東大も書けて、書けないのは図そのものが答えになっているときだけだった。

問題結果なぜそうなるか
チェバの定理 の練習型で書ける 三角形と3本のチェバ線は定理の標準図。数値が変わっても図は同じなので、型1つで足りる
2016 灘中 1日目作図で書ける 型は無い。「内分点」「垂線」「交点」の3語で書き下せる。BD:DC = 3:2 も垂直も、図の上で厳密に成立する
接線と弦の作る角(証明)作図で書ける 2円の交点と直線と円のもう一方の交点が要る(語彙を2つ足した)。 結論の AD ∥ BC は指定していないのに 0.000° で出る — 作図が正しい証拠にもなる
2019 東大 理系 第2問半分 配置は書ける(正方形・辺上の3点・2つの三角形)。ただし P・Q・R の位置は「面積がどちらも 1/3」から解いて出す数で、作図では決まらない。 作図は「解いた結果を図にする」ところまで
2020 東大 理系 第2問図が答え そもそも問題文に図が無い。要るのは 「2 ≤ △ABX+△BCX+△CAX ≤ 3 を満たす X の範囲」という答えの図で、 解かないと形が決まらない。ただし解けたあとなら書ける — 領域の境界が何であるかさえ分かれば、頂点は三角形から作図できる

結論。作図の語彙は「解いた結果を表現する」ためのもので、解く力そのものではない。 そしてそれで困らない — 先輩はどのみち、教えるために問題を解いている。 図が描けないのは解けていないときだけで、それは図の問題ではなく授業の問題になる。 足りない語彙が出てきたら足す(今回2つ足した)という進み方でよく、 最初から全部そろえる必要はない。
