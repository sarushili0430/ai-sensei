# ADR 0006: 自習室モードを畳み、コアループの内側だけをコアコンピテンシーとして固める

- ステータス: 承認
- 日付: 2026-08-11
- 関連: [`pivot_plan_v1.md`](../pivot_plan_v1.md) §0-8 / §4-2 / §6-3 /
  [`inception-deck.md`](../inception-deck.md) §4 /
  [`0004-motion-and-onboarding.md`](0004-motion-and-onboarding.md)

## 背景

ピボット計画(2026-08-09)の決定 #8 で「同席型(自習室)をやる。ただし原価ゼロで
実装する」を採り、`/study-room` を常設タブの1枝として実装した。中身は3つ:

- 画面に先輩がいる(表情つきの顔と、経過時間から引く定型の吹き出し)
- さっきの板書が残っている
- タイマーが回っている。退室時に滞在秒数を1回だけ内部指標へ送る

**原価ゼロという設計目標は達成できていた。** STT / TTS / LLM / LiveKit は1つも
起動せず、通信は退室時の小さなD1書き込み1回だけだった。畳む理由は原価ではない。

問題は、**この画面がコアループのどこにも接続していない**ことだった。

1. **先へ進む道が1本しかなく、それはホームと同じだった。** 自習室から出られる
   のは「先輩、ちょっといい?」= 撮影 → 授業モードだけで、これはホームの
   「先輩に教わる」と同じ行き先。常設タブを1つ使って、既にある入口を複製していた
2. **滞在時間は、生徒に返せない数字だった。** 約束2(点数を出さない)により
   「学習時間」を進捗へ足せないので、`/v1/me/progress` にも親レポートにも
   載せられない。実際、集計は運営がWorkers Logsで見るためだけに存在していた。
   **生徒の画面に一度も出ない数字のために、常設タブとD1の表を1つずつ持っていた**
3. **ホームの主操作が2本に割れていた。** 先輩が今日を締めた日だけ自習室ボタンが
   主役の色に変わる作りで、「押せるほうがどちらか」を色で見分けさせていた。
   締めた日の行き先としては、コアループの内側にある**復習**のほうが正しい

つまり自習室は、原価ではなく**注意**を使っていた。UI/UXを固める前に、
どれがコアかを先に決める必要があった。

## 決定

### 1. 自習室モードを削除する

モバイルの画面・ルート・タブ・文言・声かけのプリレンダ音声、契約の
`POST /v1/me/study-room`、D1の `study_room_daily`、そのすべてを消す。

常設タブは**ホーム / 計画 / 設定の3つ**になる。カルテをタブにしない判断は
変わらない(授業直後にしか意味を持たない画面を常設すると、授業前には
中身のない場所が常に見えてしまう)。

### 2. これ以降、コアコンピテンシーは「1周」と定義する

```
撮る → 先輩が板書つきで教える → 教え返す → カルテ(言えたこと・穴)→ 小テスト
                                                            ↓
                                    1日 / 3日 / 7日後の通知 → 復習 → 穴が埋まる
```

これを取り囲むもの — 学習計画(§4-3)・親レポート(§5-1)・課金(§6)・
オンボーディング — も**残す**。落としたのは、この図のどこにも矢印が刺さって
いなかった自習室だけ。以後の作業は、この範囲の**作り込み**に閉じる。

### 3. 板書はカルテへ移す(捨てない)

自習室が持っていた価値のうち、**さっきの板書が残っていること**だけは実体があった。
授業中の板書は会話画面(AutoDispose)と一緒に消えるので、自習室を消すと板書を
読み返す場所がアプリから無くなる。

`LastBoardController` を `features/study_room/` から `features/karte/` へ移し、
カルテ画面に「先輩が書いたもの」の節として出す。カルテの読む順は
**結論 → 根拠 → 操作**になる:

| 節 | 何か |
| --- | --- |
| 言えたこと / 穴 / 用語メモ | 今日の結論 |
| **先輩が書いたもの(板書)** | その根拠。穴の話をしている最中に「どこの話か」を指し直せる |
| あと追い質問 / 自己申告 / 通知の許可 | 手を動かすもの |

板書を先頭に置かないのは、長い板書が結論を画面の外へ押し出すため。

**カードに入れない**制約も一緒に移す。`BoardStyle.latexMinScale`(70%)は
実効幅340ptでの実測から決めた値で、カルテの `ListView` の余白
(`AppSpacing.lg` × 2 = 48pt)は `BoardStyle.horizontalPadding` と一致している。
ここに `padding` + `border` のカードを足すと311ptまで落ち、実測で「収まる」と
確認した式が横スクロールへ落ちる(しかも `debugPrint` にしか出ない)。

### 4. ホームの主操作は、常に1つだけにする

並べるのをやめ、**同じ場所のボタンの中身を差し替える**。

| 状態 | ラベル | 行き先 |
| --- | --- | --- |
| 授業ができる | 先輩に教わる | 撮影(`push` — やめれば戻れる) |
| 先輩が締めた・穴がある | 埋めにいく穴 | 復習(無料。原価が発生しない側) |
| 先輩が締めた・穴が無い | 先輩に教わる(押せない) | — |

締めた日の行き先を復習にしたのは、**上限に当たった人の道をホームで途切れさせない**
ため。自習室が担っていた役目のうち、コアループの内側に元からあったのはこちら。
あわせて、締めた日はあいさつも「今日は、どこでつまずいた?」から
「今日はよくがんばったね」へ変える(撮らせない画面で撮影を促さない)。

## 影響

- **原価**: 変わらない。自習室は従量原価を1つも起動していなかった
- **賞**: Design Award の材料が「先輩が隣にいる画面」から
  「板書つきで教える授業モード + カルテ」へ寄る。板書は残っているので素材は減らない。
  OneSignal 賞の材料は元から間隔反復(小テスト起点の1/3/7日通知)で、
  滞在時間はそこに使っていなかった
- **DB**: `0007_drop_study_room.sql` で `study_room_daily` を落とす。0006 のファイルは
  消さない(適用済みの本番DBでは、ファイルを消しても表は残り続けるため)。
  消えるのは滞在秒数とローカル日付だけで、学習内容はもともとこの表に無い
- **文言・音声**: 声かけ3種(`study_room_going` / `_break` / `_long`)の
  プリレンダ音声を削除。残るのは授業冒頭の `lesson_opening` 1種

## 却下した代案

**A. 自習室を残し、タブから外して寄り道(`push`)にする。**
常設タブは空くが、「先へ進む道がホームと同じ」も「滞在時間を生徒に返せない」も
そのまま残る。置き場所の問題ではなかったので、直らない。

**B. 滞在時間を進捗に足して、生徒にも見せる。**
約束2(点数を出さない)を破る。連続日数と埋めた穴に続く3つ目の数字は、
学習時間ランキングへ最も近い形をしている(§5-2 の「載せない」側)。

**C. 自習室に問題演習を持たせて、コアループへ接続する。**
「詰まったら先輩を呼ぶ」までは自然だが、演習問題を出すには生成が要る。
原価ゼロの前提が崩れ、無料である説明(§6-3「原価が発生する生成・音声だけが有料」)を
書き直すことになる。それは自習室を残すためだけに払うには大きすぎる。
