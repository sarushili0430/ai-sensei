# 価格とプラン

会話1分ごとに原価がかかるアプリなので、**価格は「いくらなら売れるか」ではなく
「いくらまで使わせるか」とセットでしか決まらない**。ここは3つをまとめて書く。

1. プランと上限(何を売るか)
2. Apple 側の設定(そのまま入力する値)
3. 実装で直すところ(いまのコードとの差分)

前提の数字は [§2](#2-なぜこの数字か) に置いてある。為替・各社の料金・
LiveKit の実課金で動くので、**桁と傾向を信じて、絶対値はメータリングで更新する**。

---

## 1. 結論

### プラン

| | 期間 | 価格(税込) | 手取り | 月あたり手取り |
| --- | --- | --- | --- | --- |
| 週額 | 1週間 | **¥580** | ¥448 | ¥1,942 |
| 月額 | 1か月 | **¥1,280** | ¥989 | ¥989 |
| 年額 | 1年 | **¥12,800** | ¥9,890 | ¥824 |

手取り = `(価格 ÷ 1.1) × 0.85`。消費税10%を抜いて Apple の手数料15%を引いた額
(**Small Business Program に登録している場合**。未登録は30%なので手取りが2割減る)。

### 上限

| | Free | Premium |
| --- | --- | --- |
| 1回の長さ | 5分 | **10分**(現状の15分から短縮) |
| 1日 | 1回 | **3回** |
| 1週間 | 制限なし | **7回** |
| カルテ | 当日のみ | 履歴すべて |
| 穴の復習 | ✗ | ○ |
| あと追い質問 | ✗ | ○ |

**「無制限」は売らない。** いまの実装(`entitlement.ts`)は Premium を文字通り
無制限にしていて、1人で月2,000分使える。原価に換算すると1人あたり月1万円を超える。

### 設計の原則(価格を動かすときも、ここは動かさない)

1. **無制限を売らない。** 上限のない従量原価は、成功するほど赤字になる。
   このアプリはストリーク・間隔反復・プッシュで**毎日使わせる設計**なので、
   エンゲージメントが効いた瞬間にヘビーユーザーが量産される。
2. **上限は週次で持つ。** 月次だと週額プランの人が1週間で月ぶんを使い切れる。
   週次なら全プランで同じ比率になる(週額 ¥580 ↔ 週7回 = 常に黒字)。
3. **年額の割引は小さく(15〜20%)。** 一般的な「年額は40%オフ」は、
   限界原価がほぼゼロのソフトウェアの話。こちらは年払いでも使われたぶん原価が出るので、
   割引の原資は CAC と解約率の改善ぶんしかない。
4. **上限は隠さず書く。** 商品説明・ペイウォール・アプリ内の3か所で同じ数字を出す。
   HAMM賞の評価軸でもあるが、それ以前に**上限のある商品を無制限として売ると返金対象**になる。

## 2. なぜこの数字か

### 2-1. 1分あたりの原価

いまの実装(`backend/agent/src/agent.ts`)が会話1分で叩くもの。¥150/$ 換算。

| | 実装 | 1分あたり |
| --- | --- | --- |
| STT | Deepgram `nova-2-general` streaming | 約 ¥0.9 |
| TTS | ElevenLabs `eleven_flash_v2_5` | 約 ¥1.4 |
| 会話LLM | Claude Haiku 4.5 | 約 ¥2.7 |
| LiveKit | 参加者2 + エージェント常駐 | 約 ¥2.0(要実測) |
| **合計** | | **約 ¥7** |

セッション単位で別途かかるもの: 写真解析(Sonnet 5・約¥5)と
カルテ生成(Sonnet 5・約¥5〜8)で、**1セッションあたり約¥10の固定費**。

会話LLMが高いのは、**システムプロンプト(約3,000トークン)を毎ターン再送している**から。
`prompts/` の3ファイル(会話・few-shot・数式ヒント)で計8KB あり、15分の会話だと
入力トークンの6割以上が同じ内容の再送になる。プロンプトキャッシュを入れると
会話LLMが ¥2.7 → ¥1.0 前後まで落ち、**合計 ¥7 → ¥5.3**。

> 以下の試算は **¥5/分 + ¥10/セッション**(キャッシュ導入後)を使う。
> 導入前は ¥7/分なので、下の粗利はさらに2〜3割薄くなる。

### 2-2. 利用の分布と、平均原価

10分セッションを1回 = ¥50 + ¥10 = **¥60/回**。

| | 割合 | 使い方 | 月の回数 | 月の原価 |
| --- | --- | --- | --- | --- |
| ライト | 50% | 週2回 | 8回 | ¥480 |
| ミドル | 35% | 週5回 | 20回 | ¥1,200 |
| ヘビー | 15% | 上限まで | 30回 | ¥1,800 |

加重平均 = **¥930/月**。ただしこれは1回を必ず10分使い切る前提。
実際の自己説明セッションは5〜8分で終わるので、実効は **¥700〜800/月** に落ち着く見込み。

### 2-3. 分岐点

| 月額 | 手取り | 平均原価 ¥750 との差 | 粗利率 |
| --- | --- | --- | --- |
| ¥580 | ¥448 | **−¥302** | 赤字 |
| ¥980 | ¥757 | +¥7 | 1% |
| **¥1,280** | **¥989** | **+¥239** | **24%** |
| ¥1,480 | ¥1,143 | +¥393 | 34% |

**¥980 は粗利がゼロ。** 決済手数料の外にあるサポート・インフラ・税を吸えない。
¥1,280 を下限、¥1,480 を安全側とする。ここでは通しやすさを取って **¥1,280**。

週額と年額も同じ物差しで見る。

- **週額 ¥580**: 手取り ¥448。週7回の上限に張り付いても原価 ¥420 なので、
  **最悪ケースでも黒字**。上限を週次にしたことがそのまま効いている。
- **年額 ¥12,800**: 月あたり手取り ¥824。平均原価 ¥750 に対して粗利 9% と薄い。
  これ以上割り引くと赤字になるので、**年額の割引はここが限界**。
  月額 ¥1,280×12 = ¥15,360 に対して17%オフ。

### 2-4. 無料枠

1日1回 × 5分 = **¥35/日**。毎日来る無料ユーザーは月 ¥1,000 かかる。
Premium 1人ぶんの粗利を、払っていない1人が食う計算になる。

それでも **無料枠はいまのまま触らない**。1日1回はストリークと間隔反復の土台で、
ここを削ると製品の中心にある習慣ループが壊れる。獲得コストとして持つ。

ただし **DAUあたり原価の最大の出所はここ**なので、メータリング(§4 P2)が入ったら
最初に見る数字にする。効かせるなら回数ではなく **1回の長さ(5分 → 3分)** から。

## 3. Apple 側の設定

App Store Connect > アプリ **かたるて** > 収益化 > サブスクリプション。
署名・App ID・契約まわりは [`ci/store-setup.md`](ci/store-setup.md) が正。ここは商品の中身だけ。

### 3-0. 先に Small Business Program に登録する

**Business > App Store Small Business Program**。手数料が 30% → **15%** になる。
自動では適用されない。**申請しないと手取りが2割減る**(月額 ¥1,280 で ¥989 → ¥726)。
売上100万ドル未満が条件なので、いまは確実に通る。

有料App契約(Paid Applications Agreement)が未締結だと、そもそも商品を作れない。

### 3-1. サブスクリプショングループは1つだけ作る

| 項目 | 値 |
| --- | --- |
| 参照名(内部) | `Premium` |
| 表示名(ユーザーに見える) | `かたるて Premium` |

**分けてはいけない。** 無料トライアルの権利は**グループにつき1回**なので、
週/月/年を別グループにすると、順に契約して**トライアルを3回タダ取りできる**。
同一グループなら週↔月↔年の乗り換えも Apple 側が処理してくれる。

### 3-2. 商品を3つ作る

> **製品IDは後から変更も再利用もできない。** 消してもそのIDは二度と使えない。
> 打つ前に3回読むこと。

| 参照名 | 製品ID | 期間 | 価格 | レベル |
| --- | --- | --- | --- | --- |
| Premium Yearly | `jp.co.aisensei.premium.yearly` | 1年 | ¥12,800 | **1** |
| Premium Monthly | `jp.co.aisensei.premium.monthly` | 1か月 | ¥1,280 | **2** |
| Premium Weekly | `jp.co.aisensei.premium.weekly` | 1週間 | ¥580 | **3** |

- **製品IDは全部小文字**にする。バンドルIDは `jp.co.aiSensei`(大文字S)だが、
  製品IDは別の名前空間で、こちらも大文字小文字を区別する。
  変更できない文字列で `S` の有無を間違えると詰むので、揃えずに小文字で通す。
- **レベルは 1 が最上位**。上位への乗り換えは即時反映＋日割り返金、
  下位への乗り換えは次回更新時。年額を1にしておくと、週額の人が年額に移った瞬間に
  年額ぶんを回収できる。逆(年→週)は期限まで年額のまま。
- 価格は Apple の価格ポイントに無い場合があるので、**いちばん近いものを選ぶ**
  (¥12,800 が無ければ ¥12,000 側に寄せる。上に寄せない)。

> **値上げは既存の契約者に自動適用されない**(同意が要り、無視されると解約になる)。
> 「まず安く出してあとで上げる」は効かないので、最初の価格を決め切ること。

### 3-3. ローカライズ(日本語は必須)

表示名と説明に**上限をそのまま書く**。こことサーバ実装がずれるのが最悪の壊れ方。

| | 表示名 | 説明 |
| --- | --- | --- |
| 月額 | `Premium(月額)` | `1日3回・週7回まで、1回10分の会話。穴の復習と履歴、後輩のあと追い質問が使えます。` |
| 年額 | `Premium(年額)` | 同上 + `月あたり ¥1,066。` |
| 週額 | `Premium(週額)` | 同上 |

### 3-4. 無料トライアル

**サブスクリプション特典 > 導入オファー > 無料 > 7日間**。

| | トライアル |
| --- | --- |
| 月額 | **7日間** |
| 年額 | **7日間** |
| 週額 | **付けない** |

週額に7日の無料を付けると**1周期まるごとタダ**になり、解約されて終わる。

トライアル1人あたりの原価は、週7回の上限があるので **7回 × ¥60 = 最大 ¥420**。
転換率40%なら1契約あたり約¥1,050 で、月額1か月ぶんの手取りで回収できる。
**上限設計がトライアルの費用も同時に抑えている**(グループ1つ = 生涯1回、も効く)。

### 3-5. 請求の猶予期間(Billing Grace Period)

**オンにする。選べる中でいちばん長いものを選ぶ。**

カード期限切れなどの「払う気はあるのに失敗した」解約を拾える。解約理由のうち
無視できない割合がこれで、いちばん安い収益改善になる。

> **先に `backend/api/src/routes/webhooks.ts:51` を直してから有効にすること。**
> いまのコードは `BILLING_ISSUE` で即座に Premium を剥奪する。猶予期間中は
> Apple/RevenueCat 側で権利が生きているのに**サーバだけ無料に戻る**ので、
> 「払っているのに使えない」が起きる。詳細は §4 P3。

### 3-6. そのほか

- **審査用スクリーンショット**: 商品ごとに必要。ペイウォール画面を撮る。
  無いと審査で弾かれる。`apps/mobile/test/golden/goldens/paywall.png` は
  自前ペイウォールの golden なので下敷きにはなるが、提出は実機/TestFlight の画面がよい。
- **ストリームライン購入**: いまオンになっている。**そのままでよい**
  (アプリ外からも契約できるぶん入口が増える)。再獲得オファーを入れる段階で見直す。
- **App Store Server Notifications V2** の URL を RevenueCat に向ける
  ([`ci/store-setup.md`](ci/store-setup.md) 1-10-3)。

配線そのものは [`revenuecat.md`](revenuecat.md) が正。ここでは入れる値だけ。

## 5. 実装で直すところ

### P0 — 価格を出す前に必ず

**1. アプリに焼かれた価格を消す**

`apps/mobile/lib/src/l10n/strings.dart:184` の `paywallPrice` が
`Premium ¥580/月 ・ はじめの7日間は無料` を直書きしている。使用箇所は2つ:

- `features/monetization/presentation/paywall_screen.dart:169`
- `features/session/presentation/celebration_screen.dart:63`

App Store Connect で ¥1,280 にした瞬間に**アプリの表示が嘘になる**
(価格の不一致は審査の指摘対象でもある)。ストアが返す `plan.priceString` と
`plan.freeTrialDays` から組み立てる形に変える。同じ画面の下half
(`paywall_screen.dart:303`)はすでに `plan.priceString` を使っているので、
上のリード文だけが取り残されている状態。

鍵の無いビルド(golden・CI)では `plans` が空になるので、
**価格を出さない文言**にフォールバックさせ、`goldens/paywall.png` を撮り直す。

**2. 比較表を実態に合わせる**

`strings.dart:199-200` の `paywallOncePerDay`(`1日1回`)と
`paywallUnlimited`(`無制限`)。**`無制限` は売らないので消す**。
`1日3回・週7回` に置き換える。`home_screen.dart` の
`remainingSessionsUnlimited`(`strings.dart:68`)も同じ理由で使わなくなる。

### P1 — 上限をサーバに入れる

**3. Premium の日次・週次上限**

- `backend/api/src/env.ts:59-71` の `Limits` に `premiumSessionsPerDay` と
  `premiumSessionsPerWeek` を追加。`readLimits()` は既存の `toInt` を使い回せる。
- `backend/api/wrangler.toml` の `[vars]`(local / develop / production の3か所):

  ```toml
  PREMIUM_SESSION_MAX_SECONDS = "600"   # 900 から短縮
  PREMIUM_SESSIONS_PER_DAY    = "3"
  PREMIUM_SESSIONS_PER_WEEK   = "7"
  ```

- `backend/api/src/lib/entitlement.ts:33-40` の premium 分岐。いまは
  `remainingToday: null` を返して素通ししている。ここで `sessionsToday` と
  `sessionsThisWeek` を見る。無料側と同じ仕組みがすでにあるので、形は揃う。
- `repository/types.ts:90` の `countSessionsOnDate` の隣に
  `countSessionsInRange(deviceId, fromLocalDate, toLocalDate)` を足す
  (D1 は `BETWEEN` 1本、memory 実装はフィルタ1行)。
  呼び出しは `routes/sessions.ts:65` の直後。

**4. エラーコードを分ける**

`free_limit_reached` を使い回さない。**払っている人に「無料枠の上限です」と
言うのは嘘**になる。`packages/contract/src/api.ts:232` の `apiErrorCodes` に
`plan_limit_reached` を追加 → `backend/api/src/lib/errors.ts:8` の `messages` に
ja/en と status(429)→ アプリ側 l10n に文言。

**5. 残数表示の出し分け**

`remaining_sessions_today` が Premium でも数字を返すようになる。
契約(`contract/src/api.ts:91`)は `nullable` のままでよいが、アプリ側が
「`null` = 無制限」を前提にしている:

- `home_screen.dart:165-174` の分岐
- `strings.dart:63-67` は文言が「今日の**無料**セッション」なので Premium 用が要る
- `karte_controllers.dart:28-33` の楽観更新はそのまま動く(数値なら減る)

### P2 — 原価を半分にする

**6. プロンプトキャッシュ**(いちばん効く)

`backend/agent/src/agent.ts:57` の `anthropic.LLM`。システムプロンプトが
毎ターン再送されている。`@livekit/agents-plugin-anthropic` が `cache_control` を
通せるかを**まずスパイクで確かめる**。通せない場合は、

- `prompts/kohai_conversation.ja.md` + `question_types.few_shot.ja.md` +
  `math_speech_hints.ja.md`(計8KB)を会話用に圧縮する
- few-shot は会話から外し、カルテ生成側にだけ残す

会話LLMが ¥2.7/分 → ¥1.0/分 になれば、全体が ¥7 → ¥5.3/分。**粗利がこれで決まる。**

**7. セッション長を 900 → 600 秒**(P1-3 と同じ変更)

15分は自己説明の単位として長すぎる。5〜8分で終わる会話に15分の枠を与えても
価値は増えず、上限まで使う人のぶんだけ原価が増える。

**8. メータリング**

`env.ts:10` で `METER` KV を宣言したまま**未使用**。
`routes/complete.ts:60` に `duration_seconds` が来ているので、まず
**デバイス別・日別の合計分数**を KV に積むだけでも上の試算を実測に置き換えられる。
LLMトークンと TTS 文字数は agent 側から内部エンドポイントに送る。

見る順番: ①DAUあたり分数 ②無料ユーザーの原価合計 ③Premium の分布(上限への張り付き)。

### P3 — 取りこぼしを減らす

**9. `BILLING_ISSUE` で剥奪しない**

`backend/api/src/routes/webhooks.ts:51` の `revokingTypes` から外す。
RevenueCat の `BILLING_ISSUE` は「課金に失敗した」であって**失効ではない**。
猶予期間(§3-5)を有効にすると、猶予中はまだ権利が生きている。
失効時には `EXPIRATION` が別に飛んでくるので、剥奪はそちらに任せれば十分。

いまのままグレースピリオドを入れると、**払っている人が使えなくなる**。

**10. ペイウォールの接点を増やす**

`entitlement.ts:74-81` の `shouldShowPaywall` は「初回カルテで穴が見えた直後の1回だけ」。
煽らない方針(HAMM)は保ったまま、**静かな導線だけ**足す:

- 無料枠を使い切ったとき(`free_limit_reached` を返す画面)
- 前日以前のカルテを開こうとしたとき

## 7. 見直すトリガー

- メータリングの実測が **¥5/分から±30%以上ずれた**とき → §2 の全表
- プロンプトキャッシュが**入らないと分かった**とき → 価格を ¥1,480 に上げるか、
  1回を8分に縮める
- 上限に張り付く人が **Premium の20%を超えた**とき → 週7回を週5回に
- LiveKit の無料枠を使い切ったとき → §2-1 の ¥2.0/分 を実額に差し替え
