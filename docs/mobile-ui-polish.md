# Mobile UI polish

このPRは、現行モバイルUIを別物へ作り替えず、学習の流れを分かりやすくするための
デザイン検討場所です。現時点の成果物は静的なレビュー用HTMLであり、Webサイトとして
公開するものでも、Flutter実装を含むものでもありません。

レビュー用ボード: [`wireframe_board_v3.html`](./wireframe_board_v3.html)

## 強化する4つの学び

1. 問題を見せ、先輩の板書を見ながら一緒に解き、自分の言葉で教え返す
2. 言葉が止まった箇所をカルテに残し、1日・3日・7日後に短く復習する
3. テスト日・範囲・教材を先輩との会話で確認し、無理のない計画を作る
4. 本人が確認した月次の学びを、点数や比較なしで家族へ共有する

## v3.3で守ること

- 現行の丸ゴシック、白い問題用紙、全幅の黒板、先輩の顔、太いボタン、3タブを保つ
- 黒板をチャットやカードで狭くせず、式・グラフ・表・図形を読みやすくする
- 先輩の直近発話を3行まで表示し、全文はスクロールで読めるようにする
- 録音中も黒板・直近の問い・先輩のことばを消さない
- 音声は長押しではなく、タップで開始してタップで終了する
- カメラとAndroid Photo Pickerを同じ入口に置き、ノート追加は任意にする
- 設定は学習プロフィール、授業と入力、復習通知、契約、サポート、データ管理で整理する
- 点数、正答率、達成率、ランキング、残回数、学習を急かす表現を出さない
- 「まだ言えない」「今日はあとで」を失敗扱いしない

## 実装時の確認方針

- 画面ID単位で小さく実装し、レビュー可能なコミットに分ける
- Androidエミュレーターで初回導入、画像入力、授業、復習、計画、家族共有、設定を確認する
- 音声状態、戻る操作、権限拒否、切断復帰で問題・板書・発話が不用意に消えないことを確認する
- UI変更に応じてgolden testを更新し、`flutter analyze`、関連テスト、debug APKビルドを通す
