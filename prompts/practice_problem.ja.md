さっき先輩が板書で教えた内容から、**3日後にもう一度たずねる復習問題を1問**作ります。
出力はJSONのみ。

## これは何のための問題か

生徒は授業の最後に画面の「わかった」を押しました。**本人が到達を宣言した**ので、
3日後・7日後に「ほんとうに残っているか」をたずねます。

- **採点します。**あなたが書いた `answer` と、生徒が書いた答えを突き合わせます。
  だから **`answer` が1つに定まらない問いは作れません。**
- 生徒はこの問題を**通知から開いて、テキストで答えます。**
  声ではありません(電車の中かもしれない)。**30秒で終わる**分量にしてください。

## 材料

授業で扱った問題:

```
{{problem_text}}
```

板書に出した手順(上から順):

```
{{board_recap}}
```

扱ってよい単元:

```
{{allowed_topics}}
```

## 作り方

1. **板書の主題を1つ選びます。**板書には複数の手順がありますが、問うのは1つだけ。
   いちばん「これが分かっていないと次で詰まる」ところを選んでください。
   授業の枝葉(計算の途中の1行、用語の言い換え)は選ばない。

2. **板書に出た数値をそのまま使わないでください。**これは**類題**であって、
   同じ問題の再出題ではありません。同じ数字で聞くと、3日後に思い出すのは
   解き方ではなく**答えの数字**になります。係数や設定を変えて、
   同じ手順を踏まないと解けない形にしてください。

3. **正解が1つに定まる形にします。**「〜について説明できる?」は作れません
   (採点できないので)。「〜はいくつ?」「〜は何個?」「この文を〜に直すと?」の形。

4. **10秒で読める長さ**(1文、40字程度)。長い設定を書かない。

5. `topic_id` は**扱ってよい単元のIDから選びます。**板書の主題に一番近いもの。
   一覧に無いIDを書かないでください。

6. `answer` は**とちゅうの式を含めて短く**書きます。生徒は「D = 36 − 20 = 16 で 2個」
   のように途中式ごと書いてくることが多く、採点はその全体を読むので、
   答えの数字だけだと「合っているのに読み取れない」が増えます。

## 出力

```json
{
  "topic_id": "M1-NIJI-HANBETSU",
  "question": "x² − 6x + 5 = 0 の解の個数は?",
  "answer": "D = 36 − 20 = 16 で D > 0 なので 2個"
}
```

- このJSON以外は何も書かないでください(前置きも、説明も、コードフェンスの外の文も)。
- `question` と `answer` は**日本語**で書いてください。
- 板書に十分な中身が無く、問題を作れないときは `{"topic_id": null}` を返してください。
  **無理に作らないでください。**教わっていないことを3日後にたずねるのが、
  このアプリでいちばん悪い失敗です。
