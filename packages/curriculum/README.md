# @ai-sensei/curriculum

カリキュラムマップ。**後輩AIが触れてよい話題の全集合**であり、同時に「穴」のタグ付け語彙でもある。

| 科目 | 範囲 | topic_id の接頭辞 |
| --- | --- | --- |
| 数学 | 高校数学(新課程・2022年度〜)の6科目 | `M1` `MA` `M2` `MB` `M3` `MC` |
| 英文法 | 高校英文法(英語コミュニケーション・論理表現で扱う文法事項) | `EG` |

- 実体は `data/curriculum.v0.json` の純JSON。TypeScript以外(Flutter・Python版agent)からも
  同じファイルを読めるようにしている。
- `src/` は読み出しヘルパと整合性チェック。**データを変えるのはJSONだけ**。

**1セッションで扱えるのは1科目だけ。** ノート1枚は1科目、という前提を、
写真解析(`subject` の判定)と許可リストの組み立ての両方で守る。

## 使い方

```ts
import {
  isKnownTopicId,
  subjectOfTopicId,
  suggestTopics,
  prerequisitesOf,
} from "@ai-sensei/curriculum";

// サーバ側ガード: LLMが返したtopic_idがカリキュラム内か
isKnownTopicId("M2-ZUKEI-ENCHOKU"); // true

// そのIDがどの科目か(セッションの科目を決めるのもこれ)
subjectOfTopicId("EG-KANKEISHI-DAIMEISHI"); // → "英文法"

// 写真解析テキストから単元候補を引く。**科目が決まっていれば必ず渡す**
suggestTopics("中心と直線の距離 判別式", 5, { subject: "数学" });

// 穴の深掘り: 「そもそも判別式って何のためにある?」の質問先を決める
prerequisitesOf("M2-ZUKEI-ENCHOKU"); // → [M1-NIJI-HANBETSU, M2-ZUKEI-TENTO-KYORI]
```

`suggestTopics` に科目を渡さないと、「比較」「否定」「省略」のような
**どちらの科目にもある日本語**で取り違えが起きる(数学のノートの「比較」で
英文法の比較表現が候補に出る)。科目が決まっている場面では必ず絞ること。

## トピックを追加するとき

```jsonc
{
  "id": "M2-ZUKEI-ENCHOKU",       // {コース接頭辞}-{単元}-{トピック} を大文字ローマ字で
  "course": "数学II",              // 接頭辞と一致していないとCIで落ちる
  "unit": "図形と方程式",
  "topic": "円と直線の位置関係",
  "goals": [                       // 質問生成のネタ元。最低1つは説明を問える形にする
    "中心と直線の距離dと半径rの比較で位置関係を判定できる",
    "2つの方法の使い分けの理由を説明できる"
  ],
  "prerequisites": ["M1-NIJI-HANBETSU"],  // 穴の深掘り先。存在するIDのみ・同じ科目のみ
  "keywords": ["円の方程式", "判別式"]     // 写真解析テキストとの突き合わせ用
}
```

科目を足すときは `subjects[]` にコースを登録し、`src/schema.ts` の
`subjects` / `courseNames` / `courseCodes` / `courseCodeByName` を合わせる。
`topicIdPattern` は `courseCodes` から組み立てているので、正規表現を手で直す必要はない。

チェックは `pnpm test` の中で回る:

- スキーマ(zod)— 未知フィールドは `strict()` で弾く
- ID重複 / 未定義の前提 / 自己参照 / 循環
- IDの接頭辞と `course` の一致 / `subjects[]` に無いコース
- **科目をまたいだ前提** — 前提は許可リストに入るので、またぐと
  数学のセッションで英文法の質問が通ってしまう
- **新課程の配当** — ベクトルが数学C、統計的な推測が数学B、仮説検定が数学I にあること
  (旧課程の知識で書き足すとここで落ちる)

### キーワードの書き方(英文法で特に注意)

`suggestTopics` は照合前に**空白を落とす**ので、`have been` のような
**英語の複数語**はほぼ一致しない(語境界の判定に落ちる)。英文法のキーワードは
`現在完了` `関係代名詞` `分詞構文` のような**日本語**か、`to不定詞` `that節` `ing形`
のような**日本語混じり**で書くこと。`the` `one` のような英単語だけの語は入れない。

## v0の範囲

97トピック(数学52 / 英文法45)。

- **数学**: 数I・数IIの頻出単元を厚めに、数A/B/III/Cは主要単元を1〜3トピックずつ。
- **英文法**: 文型・時制・助動詞・受動態・不定詞・動名詞・分詞・比較表現・関係詞・仮定法・
  名詞と冠詞・代名詞・前置詞・接続詞・疑問文と否定・話法・倒置と強調の17単元。

到達目標は技能(「因数分解できる」「訳せる」)だけで終わらせず、**各トピックに必ず1つ以上、
説明を問える目標**(「〜の理由を説明できる」「〜を使い分けられる」)を入れる。
このアプリが測るのは説明であって正誤ではないので、ここが薄いと質問が
「解けますか?」「訳せますか?」になってしまう。テストで全トピックを検査している。

拡充の手順は、LLMで下書き → 人手レビュー → JSONに追記 → `pnpm test`。
