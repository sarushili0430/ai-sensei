# ADR 0006: 課程(track)を指導言語から切り離す

- ステータス: 承認
- 日付: 2026-08-11
- 関連: [`0005-locale-curricula.md`](0005-locale-curricula.md)(この上に軸を1本足すもので、
  0005 を置き換えるものではない) /
  [`packages/curriculum/README.md`](../../packages/curriculum/README.md) / `docs/mext/`

## 背景

対応教科を**中学数学・中学英語・高校数学・高校英語**に広げるにあたって、
[ADR 0005](0005-locale-curricula.md) の `CurriculumLocale`(`ja`/`en`)が
足りないことが分かった。この値は3つの別々のことを同時に決めていた。

1. **どのカリキュラムマップを使うか**(`topicsFor` / `curriculumDigest`)
2. **先輩が話す言語**(プロンプト本文・定型句・STT/TTS・通知文)
3. **ガードレールの語彙**(「わからない」の検出・答えの漏れ・範囲外の語)

「日本の中学生が英語を学ぶ」は **課程は英語 / 指導言語は日本語** で、
1つの値では表せない。`"en"` に寄せれば日本の中学生の復習が英語のTTSで始まり、
`"ja"` に寄せれば数学I〜Cのマップから英語のトピックを引くことになる。

同時に、学習指導要領を読んで分かった制約が2つある。

- **中学英語の文法事項は学年配当されていない。** 解説の付録7は「中学校」一括で
  示し、配当は各校・教科書会社の裁量と本文に書かれている。「中1でbe動詞」は
  教科書側の慣行なので、これを範囲の判定に使うと、別の教科書を使っている生徒の
  単元が消える。
- **高校英語の言語材料の一覧(付録9)が手元のPDFに入っていない。** 本文は
  「中学校の言語材料＋次に示すもの」という参照形式なので、本文だけからは
  文法項目を網羅できない。

## 決定

### 1. `CurriculumLocale` は「指導言語」に狭め、課程は `TrackId` に切り出す

`CurriculumLocale` の値は `ja` / `en` のまま**変えない**。意味だけを
「先輩が話す言語 = ガードレールの語彙」に狭める。この2つは常に同時に動くので、
分ける必要がない。

```
TrackId        hs_math_ja / hs_math_en / (以降 jhs_math_ja / jhs_english_ja / hs_english_ja)
CurriculumTrack { id, locale, subject, stage }
```

`Record<CurriculumLocale, ...>` はプロンプトとガードレールの各所にあり、
どれも「言語ごとに1本」を意味している。ここに `"ja-english"` のような値を足すと、
その全部が「課程ごとに1本」に化けて、意味が2通りになる。
`plan_sessions.locale` の `CHECK (locale IN ('ja','en'))` も同じ理由で無傷に保つ。

**1 track = 1 JSONファイル。** `curricula` を `Record<TrackId, Curriculum>` に
したので、`trackIds` に id を足してデータファイルを忘れると型で落ちる。

### 2. track も topic_id の接頭辞から引く

0005 の決定2(「ロケールは topic_id の接頭辞で判る」)を**置き換えるのではなく、
2段にする**。

```
接頭辞 → 課程 → (指導言語, 教科, 学校段階)
```

穴に付いた topic_id ひとつから通知の言語が決まる、という 0005 の性質はそのまま。
そこに「板書に使える要素(数式か例文か)」と「学校段階」が乗る。
**セッションの課程をDBに持たない**ので、マイグレーションは要らない。

接頭辞の重複禁止は「ロケールをまたいで」から「**課程をまたいで**」に強まる
(より厳しい条件なので既存のIDは無傷)。`topicIdPattern` の交替は長い接頭辞から
並べる — `J1` と `JE1` のように片方がもう片方の先頭に見える組み合わせを足した日に、
短いほうが先に部分一致するのを防ぐため。

### 3. `topicsFor(locale)` は消す

「その言語の課程を全部」という関数を残すと、課程が増えた日に
**無言でプロンプトが倍になる**。写真解析も計画の聞き取りも、`topicsFor("ja")` が
4課程185件を返すようになったことに誰も気づけない。

`topicsForTracks(trackIds[])` に置き換えて、呼び出し側に「どの課程を見るか」を
必ず書かせる。移行時にコンパイルエラーで全呼び出しを洗い出せる、という副作用も
狙っている。

### 4. 学年は「表示だけの目安」として `grade_hint` に隔離する

中学英語のトピックにだけ `grade_hint: 1|2|3` を持たせ、
**読んでよいのは `topicLabel()` ただ1つ**にする。

`suggestTopics` / `buildAllowedTopics` / `resolveDetectedTopics` には
**学年を渡す引数を作らない**。これが「学年で範囲を絞らない」という約束の実体で、
コメントや README ではなく型がそれを保証する。
`checkIntegrity` の `grade-hint-not-allowed` が、数学の課程(course そのものが
学年を表す)への混入を落とす。

中学英語の courseCode を `JE1`/`JE2`/`JE3` と学年別にしないのも同じ理由。
学年が接頭辞に入っていると、あとから誰かが接頭辞で範囲を絞る誘惑が生まれる。

### 5. 前提の参照は「同じ課程の中」から「同じ言語・同じ教科の中」に緩める

高校英語の前提は中学英語、高校数学の前提は中学数学であるのが自然で、
**「二次方程式で詰まっている高2を中3へ戻す」は先輩の中核機能そのもの**。
段(中学 → 高校)はまたいでよい。

言語をまたぐ参照(Algebra 2 の前提が 数学II)と、教科をまたぐ参照
(不定詞の前提が二次関数)は従来どおり落とす。

代償として、許可リストに前段の学年が混ざって件数が増える。現状の実測
(前提2段で2.9〜4.8件)を新しいデータで取り直し、10件を超えるようなら
段数ではなく前提の辺のほうを見直す。

### 6. 学校段階はリクエストごとに受け取り、DBには持たない

`school_stage`(`junior_high` / `high_school`)を
`createSessionRequest` / `createPlanSessionRequest` に足し、
**既定を `high_school`** にする。既定が現状の挙動なので、旧アプリも既存テストも
そのまま通る。端末は設定画面で選んだ値を `SharedPreferences` に持つ。

D1 に列を足さないので、ここでもマイグレーションは要らない。
**代償**: 再インストールで選び直しになる / サーバ側で段階別の集計ができない。
必要になってから `users` に足す。

### 7. 高校英語は v1 では文法項目一覧を作らない

付録9(言語材料の一覧)が手元のPDFに無いので、**解説本文に完全に載っている
「5領域 × 論理の型」**(意見の主張・反論・例示・結論、叙述文・説明文・論証文)で
トピックを構成する。文法の穴は `prerequisites` で中学英語のトピックを指す
— 決定5でまたげるようにしたのがここで効く。

付録9を入手したら、英語コミュニケーション側に文法トピックを足して
`prerequisites` を貼り替える。その旨をデータファイルの `note` に残す。

## 結果

- 「課程」「言語」「教科」「段階」が別々に問える。日本語で英語を教える課程が
  素直に書ける。
- 課程を足す作業がファイル1本＋接頭辞の登録で済み、忘れると型か
  `checkIntegrity` で落ちる。
- 接頭辞は3か所で二重管理されたまま(`curriculum/src/schema.ts` /
  `contract/src/karte.ts` の正規表現 / `apps/mobile` の `planSubject`)。
  contract が依存を持たない層である以上これは解けないので、
  **モバイル側は「全コースコードでフォールバックしない」テストで縛る**。
- 0005 の4つの決定はすべて生きている。訳さない・接頭辞で判る・プロンプトは
  言語ごと・ガードレールは言語ごと。

## 代替案

- **`CurriculumLocale` に `"ja-english"` のような値を足す。** いちばん小さい変更に
  見えるが、`Record<CurriculumLocale, ...>` の意味が「言語ごと」から「課程ごと」に
  静かに化ける。`plan_sessions.locale` の CHECK 制約も書き換えになり、
  マイグレーションが必要になる。
- **topic_id の形を `{教科}-{課程}-{単元}` に作り直す。** 分類としては素直だが、
  `holes.topic_id` / `kartes.topic_ids` / `study_plans` の JSON に保存済みのIDを
  全部書き換えることになる。接頭辞を足すだけなら既存データは無傷。
- **学年を courseCode に入れる**(`JE1`/`JE2`/`JE3`)。ラベルは作りやすいが、
  学年で絞れてしまう構造そのものが、指導要領が定めていない配当を
  仕様に格上げすることになる。
