# ADR 0003: 声(STT/TTS)のベンダーをDeepgramに一本化する

- ステータス: 承認
- 日付: 2026-08-06
- 関連: [ADR 0002](0002-agent-runtime.md)、`docs/handoff_to_opus.md` §5

## 背景

当初は **STT: Deepgram / TTS: ElevenLabs** の2社構成だった
(handoff §5「TTS: ElevenLabs(後輩の声を1ボイス固定)」)。ElevenLabsは
ハッカソンのスポンサー特典でもあり、プラグイン連携を維持する意図があった。

この構成を選んだ時点では、**Deepgramの音声合成(Aura)は英語圏の言語しか
喋れなかった**。このプロダクトは日本語の中学生に日本語で話しかけるので、
TTSを別ベンダーにする以外の選択肢が無かった。

その前提が変わった。Aura-2 が2025年12月に日本語対応を追加し、日本語ボイスも
複数ある。**2社に分けている理由が、技術的には消えた。**

## 決定

**STTもTTSもDeepgramにする。ElevenLabsへの依存を落とす。**

理由:

1. **障害点と請求先が1つ減る。** ソロ運用では、鍵の期限切れ・レート制限・
   障害対応の対象が2社から1社になる差が大きい。声が出ない原因を切り分けるとき、
   見る先が1つで済む。
2. **乗り換えが安い。** LiveKit Agentsがプラグインを抽象化しているので、
   差し替えは`agent.ts`のTTS構築1ブロックと設定だけ。逆方向も同じコストなので、
   **この決定は巻き戻せる**(声の質に不満が出たらElevenLabsに戻せばよい)。
3. STTは既にDeepgramで動いていて、実績のある側を残す形になる。

失うもの:

- **ElevenLabsのスポンサー連携。** これは技術ではなく座組みの判断で、
  意図的に引き受けた。他のスポンサー(Codemagic / OpenRouter / Sentry / RevenueCat)は
  そのまま。
- 表現力に定評のあるボイス。後輩キャラの声としてAura-2の日本語ボイスが
  力不足なら、そこが巻き戻しの判断基準になる。

## 声の設定

**日本語ボイスは既定値を置かず、設定必須にした**(`DEEPGRAM_TTS_MODEL_JA`)。
声はキャラクターそのものなので、選ばないまま適当なボイスで喋り出すより、
起動時に「選べ」と言われるほうがいい。

英語ロケール用に `DEEPGRAM_TTS_MODEL_EN` を別に持つ。これは
ElevenLabsとの重要な差で、**Deepgramは言語がモデル名に埋まっている**
(`aura-2-<voice>-ja`)。1ボイスに`language`を渡して日英を切り替える作りでは
ないので、日本語ボイスは英語を喋れない。ここを1つにまとめると、
`locale=en`(審査・デモ向け)が黙って壊れる。英語側は既定値で動くようにしてある。

## 結果

- 良い点: 音声まわりの鍵が1つ、請求が1つ、障害の切り分け先が1つ。
- 良い点: STT/TTSが同じベンダーなので、日本語の扱い(表記ゆれ・数式語彙)の
  相性を1箇所で調整できる。
- 悪い点: スポンサー連携を1つ失う。
- 悪い点: SDK `@livekit/agents-plugin-deepgram@1.6.1` の `TTSModels` 型は
  英語ボイスしか列挙していない(日本語対応より前のリリース)。`model` の型が
  `TTSModels | string` なので実行時は通るが、**型では守られない**。
  ボイス名の打ち間違いはAPIのエラーとして出る。
