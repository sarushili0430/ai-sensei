04 / SCOPE

実装へ移すときの境界

見た目だけの変更と、新しい仕様を分離する。最初のPRで全部を実装しない。

項目扱い理由
黒板・問題カード・下部操作の再配置既存を改善現在の授業状態とデータで作れる
学年・通知・契約・サポートの再編既存を改善機能を増やさず情報設計を直せる
OSの言語・文字サイズへの導線既存を尊重状態の二重管理を避ける
読み上げ速度・字幕・効果音新規提案保存先と音声制御の仕様決めが必要
接続待機・再接続・権限前説明新規提案異常時とOSダイアログ前の状態設計が必要
ホームの「次の一歩」既存を改善既存の復習・撮影・計画導線を優先順位づけする
空状態とサンプル新規提案初回ユーザーが価値を理解できる見本が必要
親アカウント追加しない既存の「親アカウントを作らない」方針を維持
05 / RULES

v3で守る6原則

画面を増やしても崩れないように、具体的な実装ルールへ落とす。

01 / FOCUS授業では黒板が最大

ヘッダー、問題、字幕は必要な高さだけを使う。

02 / ONE ACTION強いボタンは1画面1つ

「次へ」「話す」「ヒントを見る」を同時に強調しない。

03 / STATE色だけで状態を伝えない

説明中／あなたの番を文言、位置、操作の3つで示す。

04 / SYSTEMOS設定を尊重する

通知・言語・アクセシビリティをアプリ内で二重管理しない。

05 / DISCLOSURE技術情報は必要時に開く

端末IDやビルド番号はサポート詳細に畳む。

06 / ACCESS44px・文字拡大・動き軽減

見た目の完成度と操作可能性を同じ品質として扱う。
