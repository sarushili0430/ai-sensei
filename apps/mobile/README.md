# apps/mobile

Flutter (iOS first). Riverpod 3 + go_router.

```
lib/src/
  api/             talking to backend/api, the anonymous device id
  common_widgets/  highlighter marker, chunky buttons, the senpai's expressions
  features/        by domain (not by screen)
    onboarding/
    capture/       photo capture, unit confirmation
    session/       conversation, celebration
    karte/         karte, holes, review, streak (one domain, so kept together)
    monetization/  entitlement, paywall
  l10n/            two locales, ja and en
  routing/         go_router
  theme/           design tokens
```

Inside each feature: `presentation / application / domain / data`
(the codewithandrea layout).

## Setup

The Flutter version is pinned with **fvm** (`.fvmrc` = 3.44.8).
CI reads the same file, so the SDK never drifts between local and CI.

```bash
dart pub global activate fvm      # first time only
fvm install                       # fetch the version in .fvmrc
fvm flutter pub get
cp dart_defines/local.example.json dart_defines/local.json
tool/run.sh                       # = tool/run.sh --debug --dart_define=local
```

Without fvm, install 3.44.8 by hand (check with `flutter --version`).
`tool/run.sh` uses `fvm flutter` when `.fvmrc` and `fvm` exist, and plain `flutter`
otherwise.

### Environment variables (dart-define)

Values live in `dart_defines/*.json` and are passed straight through with
`--dart-define-from-file`. What each key means is in
[`dart_defines/README.md`](dart_defines/README.md).

```bash
tool/run.sh --debug   --dart_define=local
tool/run.sh --release --dart_define=prod
tool/run.sh --debug   --dart_define=dart_defines/staging.json
tool/run.sh --debug   --dart_define=API_BASE_URL=http://192.168.1.10:8787   # one-off override
tool/run.sh --debug   --dart_define=local -d "iPhone 15"                    # the rest passes through to flutter run
```

`--dart_define` may be repeated, and the last one wins (so you can read a file and
override a single key). `--dart-define` / `--dart-define-from-file` spellings work
too. Without the script it is just `flutter run`:

```bash
fvm flutter run --debug --dart-define-from-file=dart_defines/local.json
```

Only **public values** belong here (the API URL, RevenueCat public keys, the OneSignal
App ID, the Sentry DSN). `--dart-define` values are embedded in the build artifact and
readable by disassembly, so **do not put secrets here**. Every secret lives in
`backend/`. Nothing but `*.example.json` is committed.

## Code generation

Uses freezed / json_serializable / riverpod_generator.
**Generated files (`*.freezed.dart` / `*.g.dart`) are not committed**, because a diff
full of generated code is unreadable in review.

```bash
fvm dart run build_runner build            # once
fvm dart run build_runner watch            # while developing
```

Right after cloning, the order is `pub get` -> `build_runner build` -> `flutter test`.
CI runs the same order.

## lint

`analysis_options.yaml` is authoritative. Through `lefthook.yml` (loaded from the root
`lefthook.yml`), `flutter analyze` runs **only on commits that stage `.dart` / `.yaml`
under this directory**. It fails without the generated files, so run
`build_runner build` first.

```bash
fvm flutter analyze
```

## Tests

```bash
fvm flutter test
```

- `test/contract_fixture_test.dart` — **contract drift detection**.
  Parses `packages/contract/fixtures/*.json` with the Dart models.
  Only when both this and the TypeScript side
  (`packages/contract/src/fixtures.test.ts`) pass is the contract aligned.
- `test/widget_test.dart` — structurally confirms the design promises have not
  disappeared from the screen (the paywall's "keep using it free" and "cancel any
  time", for instance).

### golden test

`test/golden/` covers the six main screens (onboarding / home / celebration / karte /
review / paywall). Details in [`test/golden/README.md`](test/golden/README.md).

The rounded gothic typeface (SIL OFL 1.1) sits in `assets/fonts/` and is loaded by the
test before rendering. Without loading it, rendering uses Ahem (solid squares) and
broken glyphs go unnoticed.

## Building and distribution

`ios/` and `android/` are committed.

| | Identifier |
| --- | --- |
| iOS | `jp.co.aiSensei` (registered in App Store Connect) |
| Android | `jp.co.aiSensei` (changeable until the first AAB upload) |

Distribution is via Codemagic (`codemagic.yaml` at the repository root).
A push to `develop` uploads to TestFlight. Setup is in
[`docs/ci/codemagic.md`](../../docs/ci/codemagic.md).

`pubspec.yaml`'s `version` is authoritative for the version name; CI assigns the build
number.

Permission descriptions live in `ios/Runner/Info.plist` (camera, microphone, photos)
and `android/app/src/main/AndroidManifest.xml`.
Release signing is read from `android/key.properties` (not committed; without it,
signing falls back to debug, so `flutter run --release` still works).

## What happens after a conversation

The karte is generated by the agent (server side), so once the conversation ends the
app polls `GET /v1/sessions/{id}/result`. While it is generating the server returns
202, so the app polls for a few seconds.

```
conversation ends -> disconnect the room -> poll result
                  -> store karte and progress -> celebration -> karte
                  -> (only the first time, when the server says so) paywall
```

**The server decides** whether to show the paywall (`show_paywall`). The conversation
screen's controller is AutoDispose and is already gone by the time celebration and
karte appear, so the decision is carried in `sessionOutcomeProvider`.

If generation does not finish in time, `resultMissing` is set and only the celebration
is shown.
