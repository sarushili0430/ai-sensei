「板書っぽさ」は6つの部品でできている

どれか1つでは黒板にならない。逆に、全部やらなくても面と粉受けの2つで大半は立つ。

先輩の板書

判別式を見る

D = b² − 4ac

D = 16 − 4k > 0

k < 4

契約にある5要素(latex / text / plot / triangle / circle)は、すべてこの面の上で成立する必要がある。

1. 面
濃い緑〜濃紺。真っ黒にしない(本文の ink を真っ黒にしていないのと同じ理由)。ここが変わるだけで、残り5つは効きが倍になる。
2. 画面いっぱい
左右の端まで伸ばす。板は面であってカードではない。同時にこれが、実効幅を減らさずに面を作る唯一の形。
3. 縁と粉受け
上下の横木。粉受けは「黒板である」ことの最短の記号で、しかも板がどこで終わるかを同時に示せる。
4. チョークの字
白を95%の不透明度で。わずかな滲みを乗せる。書く動きは既にある — BoardReveal の左→右のワイプ(420ms)は、そのままチョークの動きとして読める。
5. 線でやる強調
下線・二重下線・囲み・矢印。黒板の強調はもともと色ではなく線。青やピンクは板の上では浮く。
6. 見出し
板の左上に小さく「先輩の板書」。いまはヘッダに board.title があるだけなので、板の中に入れると帰属が閉じる。

LPのモックと、実装の授業画面の差

貼られた画は apps/lp/public/index.html のヒーロー内のダミー端末で、 中身はオンボーディングのリハーサル(onboarding_rehearsal.dart・台本の1問)と同じ。 授業画面のスクリーンショットではない。差はスタイルではなく、存在するもの/しないもののレベルにある。

項目LPのモック実装(session_screen.dart)
撮った問題板書と並ぶブロックとして常時ある画面に無い。ヘッダに board.title が1行あるだけ
板書の器灰色のカード2枚。問題も板書も同じ素材器が無く、地に直接。実効幅340ptを守るための意図的な形

マイク「長押しして教え返す」の丸ボタンが主役長押しは無い。LiveKitで繋ぎっぱなし。ボタンは「うまく言えない」と「今日はここまで」の2つ
顔と吹き出し板書と同格の大きさで中央にいる下の帯に小さく置く(_LessonFooter)。主役は板書という配分

LPが実装より先に「こうなる」を描くこと自体は問題ではない(配信予定と明記してあり、実物のスクショは出していない)。 問題になるのはストア掲載スクショで、あちらは実コードから生成する規約になっている。 現物が古いままなので、この作業のついでに走らせ直す。
