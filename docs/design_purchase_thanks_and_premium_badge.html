DESIGN PROPOSAL / apps/mobile — monetization

お金を払った瞬間、アプリが何も言わない。

購入が通ると closeOrGoHome() でペイウォールが消えるだけで、お礼も、何が解放されたかの説明も無い。 そのあとホームに戻っても、Premium だと分かる印がどこにも無い(残り回数の行は Premium だと消える = 払った人の画面のほうが情報が少ない)。 ここを埋める案です。

いま起きていること ① 購入成功 → 画面が閉じるだけ。RevenueCat のペイウォールで買った場合も同じ。「本当に買えたのか」が分からない。
いま起きていること ② ホームの残り回数の行は Premium だと SizedBox になる。無料の人には「残り1回」が出て、払った人には空白が出る。
すでにある部品 remainingSessionsUnlimited(「セッションは無制限です」)は定義済みで未使用。紙吹雪・後輩の表情・厚いボタンも既存。新規で作るものは少ない。
守る前提 ① 煽らない(handoff §6) バッジは「自慢する印」ではなく「今どっちの状態か」の表示にする。このアプリは一人で使うので、見せる相手がいない。
守る前提 ② 数えるのは2つだけ(§7) 連続日数と埋めた穴以外は数えない。バッジがランク・称号・レベルに見えたら失敗。金色とグラデを使わない理由もこれ。
守る前提 ③ 祝うのは1回だけ(§7) にぎやかにするのは購入直後の1画面まで。カルテと復習は静かな画面なので、そこに祝いの色を持ち込まない。

PART C

推奨の組み合わせと、実装するときの注意

おすすめ:A-1 + B-1 + B-2 + B-4

  1. A-1 全画面のお礼 — 購入・トライアル・復元で見出しを出し分ける。祝うのはここ1回だけ。
  2. B-2 残り回数の行 — 「セッションは無制限です」。これが本体。空白だった行に事実が戻る。
  3. B-1 ホーム右上のチップ(T-2 枠線) — 印。押すと設定の契約セクションへ。
  4. B-4 設定のカード — 状態と次の更新日。解約予約済みなら終了日に差し替え。

B-3(後輩に印)は不採用。★は「納得した瞬間のきらり」に使っていて、意味が混ざる。

入口は3つある(ここが抜けやすい)

  • 自前ペイウォールの PurchaseSucceeded()
  • RevenueCat ペイウォールの PaywallResult.purchased
  • 復元の RestoreSucceeded()(設定からの復元も含む)
  • いまはどれも closeOrGoHome()。3つともお礼へ寄せないと、RevenueCat 側で買った人には何も出ない。

待ち時間を隠す場所として使える

  • サーバの is_premium は webhook 経由で数秒遅れる(PremiumSync がバックオフで読み直している)。
  • お礼画面を見ているあいだに追いつくので、ホームに戻った瞬間には無制限になっている。
  • 祝福画面がカルテ生成を隠しているのと同じ構造。

足すもの / 直すもの

  • ルート /thanks を1つ(/ の子ルート)。
  • 文言 ja/en:見出し3種・解放3行・更新日の注記・premiumBadge。
  • _RemainingLine:Premium で SizedBox を返している分岐を、既存の remainingSessionsUnlimited に差し替える。
  • SubscriptionStatusLine をカードに格上げ(文言はそのまま使える)。
  • golden を1枚追加。トライアル時の見出しも撮る。
