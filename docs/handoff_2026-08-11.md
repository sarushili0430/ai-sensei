## 2. 設計上、壊してはいけない約束

デッキ §0 の4つ。**1番目だけがピボットで改正**され、2〜4は無傷。

1. **教える。そのあと教え返させる。**
2. **点数を出さない。** 数えるのは連続日数と埋めた穴だけ
3. **パスを恥にしない。** 説明できなかったことは穴として価値化する
4. **煽らない。** 通知もペイウォールも先輩の判断として書く。数字は見せず、命令や催促にしない

実装で繰り返し効いている派生規則:

- **上限を数字で見せない。**「本日の残り 0/3」は不満を生む。「今日はここまでにしよっか」に倒す。
  ただし**買うかどうかを決める場所では嘘をつかない**(§4-3 の教訓)
- **AIに採点させない。**「言えたか」は本人が決める。判定を機械に渡した瞬間、
  AIの誤読を1/3/7日で3回強化する最悪の失敗モードに入る
- **ガードレールが授業を殺さない。** 板書の topic 照合は外れたら作り直すが、
  直らなくても授業は続ける。板書を止めると生徒は15分を丸ごと失う

## 3. 人間の判断が要るもの(最優先)

### 3-1. Sentry のプロジェクト作成と DSN 登録

**これが無いと監視は1件も飛ばない。** コードは3層とも通してあるが、鍵が空のまま。

- 組織 `emobi-dy` に **`ai-sensei` 用のプロジェクトが無い**。既存4つ(`emobi-app` 系・`javascript-nextjs`)は
  **すべて別プロダクト**。流用すると双方のクラッシュが読めなくなる
- platform = Flutter で新規作成 → Settings > Client Keys (DSN) をコピー
- 貼る先は2か所: `apps/mobile/dart_defines/local.json` と
  Codemagic の変数グループ `mobile-dart-defines`(**secure 不要**。DSNは公開前提の値)
- 環境の分け方は **1プロジェクト + `environment` タグ**を推奨(ソロ運用でダッシュボードを二重管理しない)

### 3-2. 未成年向けの同意フローの要否

`OneSignal.consentRequired(true)` を入れるか。**入れると `consentGiven(true)` まで SDK が丸ごと無効**になり、
同意フローが無いと**通知が1通も届かない**(OneSignal賞の根拠が消える)。

COPPA は13歳未満が対象なので直接は掛からない(Kids Category には入れない方針)。
**GDPR は EU に配信するかで決まる**ので、配信地域の決定とセットの判断。

### 3-3. 価格の確定

計画書 §6-2 は週1,200〜1,500 / 月5,000 / 年40,000 を案として置き、
**W3 のテレメトリで原価を実測してから確定**する方針。実装は Offering から引く形になったので、
**ダッシュボード側の設定だけで変えられる**。コードの変更は要らない。

## 4. コード側に残っている宿題

### 4-1. #77(修正中)— マイグレーションがデプロイの窓で本番を壊す

`deploy.yml` は**マイグレーションを適用してから Worker を deploy** する。つまり
**「マイグレーション適用済み・旧 Worker 稼働中」の窓が必ずある**。

`0003` が UNIQUE INDEX まで同時に作ると、その窓で旧 Worker の insert は `day_seq` を書かず
全行が既定値 0 になり、**その日2件目以降のセッション作成が全ユーザーで失敗する**。

**この形の罠は今後も出る。**「マイグレーションと新コードが同時に効く」前提でスキーマを変えると、
デプロイのたびに数十秒〜数分の障害窓が生まれる。**列の追加と制約の追加は別のデプロイに分ける。**

### 4-2. 日付をまたいだときに枠が更新されない(#79 のレビュー P1)

`ProgressController` が keep-alive なので、アプリを起動したまま深夜0時を越えると
`lessonAllowedToday` が前日の false のまま残る。翌日ぶんの枠があるのに「今日はここまで」が出る。

### 4-3. 通知キャンセルの ID を先に消している(#79 のレビュー P2)

OneSignal のキャンセルが通信失敗すると、外部IDは既に消え穴も埋まっているので、
500 を返すのに再試行では素通りする。**予約が残ったまま**になり、埋めた穴の通知が届く。

### 4-4. 小テストの出題元は、構造ではなくプロンプトが守っている

§2 の「**出題元はユーザーが説明した内容。AIが教えた内容から作らない**」は、
AIの誤読を間隔反復で強化しないための制約で、**この設計でいちばん重要な一行**。

当初「授業中の発話は transcript に入らないので構造で守られる」と考えたが、**半分しか正しくない**。
`addToChatCtx: false` が付いているのは**板書ステップの読み上げだけ**で、
教え返しの会話・冒頭のフィラー・締めの促しは transcript に載る。

いまはプロンプトで出題元を `ユーザー:` / `Student:` の行だけに縛り、日英ともテストで固定している。
**構造ではなく文面が守っているので弱い。** 構造で守れる形に直す価値がある。

### 4-5. その他

- **計画モードの単元照合が繋がっていない**(#24)。ガードは `packages/guardrail` にあるが、
  計画モードの画面が無いので繋ぎ先がない。**「ガードだけあって呼ばれていない」状態**なので、
  画面を作るときに必ず繋ぐこと
- **自習室の滞在時間を計測していない。** 計画書は滞在時間を OneSignal賞の材料に挙げているが、
  計測にはサーバ通信が要り §4-2 の「サーバ通信も動かさない」と衝突する。
  原価ゼロを崩さずに測る方法(アプリ内に貯めて次のセッションでまとめて送る等)は未判断
- **音声で聞き直しても自動では穴が埋まらない。** アプリで「言えた」を押すまで open のまま。
  §2 に忠実(判定者は本人)だが、授業のあとに同じ二択を出す導線は未着手
- **読み上げの質が実機未確認。** VoiceOver の日本語音声が「かっことじ」「の2乗」をどう読むかは
  実機でしか分からない。文字列は `strings.dart` の1か所に集めてある

## 5. この作業で踏んだ罠(次に同じ形で転ばないために)

### 5-1. 「文書には書いてあるが実装が無い」が繰り返し出た

今回だけで4件。**型検査でもテストでも捕まらない**種類の欠陥で、いずれも「入れたつもり」で提出まで行く。

| 主張 | 実態 |
| --- | --- |
| README「サーバ側で topic_id をホワイトリスト照合して再生成させる」 | **板書経路に照合が無かった** |
| 計画書「Sentry を提出前に必ず塞ぐ」 | **3層とも空だった** |
| golden README「PNGはCIで焼き直せ」 | **焼くワークフローが存在しなかった** |
| ci README「テンプレート側が正なので上書きしてよい」 | **テンプレートのほうが古く、従うとCIの改善が消えた** |

**定期的に「書いてあることが本当に実装されているか」を洗う価値がある。**
今回は Codex に全体監査させて8件の高を出した。

### 5-2. 「入れたつもり」— ガードだけあって呼ばれていない

`checkProblemText` / 計画の単元照合 / Sentry / `containsAnswerLeak` と、
**定義はあるが本番の呼び出し元がゼロ**という形が何度も出た。

**新しいガードや監視を足したら、呼び出し元があることを必ず確かめる。**

### 5-3. 契約の境界に型が無いと、静かに壊れる

`sessionMetadata`(LiveKitトークンに載って api → agent へ渡る封筒)が**無型のまま運用されていた**。
そのせいで「先輩が問題文を見ていない」ことに誰も気づけなかった。

型を付けたあとも、**受信側が共有スキーマを使わず自前で再定義していた**。
欄を改名しても agent のテストは手書きJSONで通り続け、実環境では全セッション切断か全員無料扱いになる。

**契約は「型を置く」だけでは足りない。両側が同じスキーマと同じ fixture を通ること。**

### 5-4. golden の目視は飛ばせない

`--update-goldens` は「**いま描けたもの**」を無条件に正として書き込む。
実際に今回、復習画面の golden が**エラー画面**を描いていて、目視で気づいた。
そのまま入れれば**壊れた画面が正になっていた**(原因はプロダクト側の欠陥で、直してから焼き直した)。

焼いたあとにテストを走らせても、それは「さっき焼いたものと同じか」を見ているだけ。

### 5-5. 見た目で気づけない不具合には、見張りを置くしかない

自習室の板書が実効幅 198pt まで痩せて式が横スクロールに落ちていたが、記録は `debugPrint` だけだった。
直すと同時に「実効幅は340ptを下回らない」テストを置き、**書いた時点で落ちる**ことを確認している。

同じ形で、レイアウトのはみ出しを全画面 × 日英 × 375×667 で掃くテストも入れた。
**同じ形のバグが3回出たら、掃く仕組みを作る。**

### 5-6. 道具まわり

- **`git add -A <dir>` で、除外したはずのものが戻る。** `test/spike/` を2回外して2回戻した。
  判断ではなく**仕組みで止める**しかないので `.gitignore` に入れた
- **worktree が持っているブランチは checkout できない。** 失敗しても後続のコマンドは走るので、
  `&&` で繋がないと**別ブランチの作業ツリーにファイルを書き込む**
- **`codex exec` は `< /dev/null` を付けないと stdin 待ちでハングする**
- **`apps/mobile` を作業ディレクトリにしたまま `biome ci .` を打たない。**
  `files.ignore` の `apps/mobile` が起点になると除外が効かず、
  シンボリックリンク経由で Flutter SDK 本体まで走査して終わらない
- **シークレット走査は tracked なファイルだけを見る。** 未追跡のうちは守られていないので、
  コミットして初めてCIで落ちることがある
- **worktree に `.fvm` が無いと pre-commit の `flutter analyze` が通らない。**
  ここで `--no-verify` に逃げないこと(今回1件発生した)
